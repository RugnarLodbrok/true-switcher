# Задача 32. Первый пробел в паттернах автосвича

## Текущее поведение

`History::process` учитывает пробелы после слова в `Word::trailing_spaces`. `Input::process_text_event` запускает проверку паттернов только для `is_text_key`, а `AutoSwitchRules::target` преобразует в текст только `Word::strokes()`. Поэтому паттерны из [задачи 19](19.md) сейчас получают слово без пробела.

## Предлагаемое поведение

1. При вводе символов проверять паттерны как сейчас.
2. После первого `Space` за словом, когда `trailing_spaces` становится равным `1`, снова проверить паттерны. Для каждого правила преобразовать слово в его целевую раскладку и добавить один обычный пробел (`U+0020`) к строке перед сравнением с `patterns`.
3. Пробелы при пустой истории и последующие пробелы за тем же словом пропускать при проверке паттернов. Фактическое число пробелов по-прежнему хранить в `trailing_spaces` для удаления и воспроизведения ввода.

Если автосвич уже ожидает выполнения, результат проверки после первого пробела обрабатывается так же, как после буквы. Первое совпавшее правило определяет цель автосвича. Если совпадений больше нет, `automatic_target` становится `None` и ожидающий автосвич не выполняется.

Например, для `patterns = ['^foo $']` слово `foo` в целевой раскладке совпадёт с паттерном после первого пробела.

## Места изменения

- В `Input::process_text_event` допустить первый `KEY_SPACE` после слова к проверке после обновления `History`. Применять существующие ограничения автосвича, включая блокировку после ручного исправления.
- В `AutoSwitchRules::target` добавить один пробел к успешно преобразованному тексту для проверки после `Space`.
