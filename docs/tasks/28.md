# Задача 28. Ручной свич отключает автосвич для текущего слова

## Поведение

После ручного исправления слова автосвич больше не должен переключать это слово, пока пользователь продолжает с ним работать. Ручной выбор имеет приоритет над автоматическими правилами.

- Дописывание букв и частичное удаление через Backspace сохраняют запрет автосвича для текущего слова.
- Повторное ручное исправление разрешено и не снимает запрет.
- Полное удаление слова снимает запрет. Повторный набор такого же текста обрабатывается обычными правилами автосвича.
- При переходе к следующему слову запрет забывается. Он не должен распространяться на следующее слово.
- Сброс контекста ввода снимает запрет вместе с историей слова: навигация, смена фокуса, клик и остальные существующие причины сброса истории.
- Текст слова не заносится в словарь исключений, конфигурацию или постоянную историю запретов. Другое вхождение того же слова не получает запрета.
- Автоматическое исправление само по себе не устанавливает запрет: существующая возможность повторного автосвича одного слова сохраняется.

## Границы слова

Использовать существующие правила `History`, не вводить отдельное определение слова для этой задачи. Сейчас пробелы хранятся в `Word.trailing_spaces`, а новое слово создаётся при вводе следующего текстового символа. Enter и Tab сбрасывают историю; знаки пунктуации обрабатываются как текстовые клавиши.

Ручной свич после слова с завершающими пробелами защищает именно исправляемое слово. Если пользователь удалил пробелы и продолжил его ввод, запрет сохраняется. При начале следующего слова запрет забывается. Возврат через Backspace к предыдущему слову не восстанавливает забытый запрет.

Под ручным свичем подразумевается исправление через настроенную клавишу `switch_key`. Смена раскладки средствами рабочего стола обрабатывается по существующим правилам сброса истории.

## Реализация

`History.is_auto_switch_blocked` хранит запрет только для текущего слова. Создание следующего слова, полное удаление текущего слова и сброс истории снимают запрет. В `Word` запрет не хранится, поэтому возврат по истории его не восстанавливает. `Input` проверяет запрет перед выбором автоматического исправления.

Учесть асинхронное исправление и пакетную обработку ввода:

- Ручной запрос и автоматический запрос различаются через `Input.is_auto_request`.
- Запрет должен относиться к слову, которое было исправлено вручную, и не переходить на следующее слово из очереди событий.
- Запрет устанавливается при успешной обработке `CorrectionFinished` для ручного запроса. Отменённое или неудачное исправление сбрасывает историю и не оставляет запрета.
- После сброса истории не должно оставаться запрета или отложенного автозапроса для удалённого контекста.

## Тесты

- После ручного исправления дописывание до совпадения с автопаттерном не запускает автосвич.
- Частичное удаление и последующее дописывание сохраняют запрет.
- Полное удаление и повторный набор, в том числе того же текста, снова разрешают автосвич.
- Следующее слово обрабатывается автоматически по обычным правилам.
- Повторный ручной свич защищённого слова работает.
- Завершающие пробелы, их удаление и продолжение слова обрабатываются согласно выбранной границе запрета.
- Сброс контекста удаляет запрет.
- Автосвич без ручного вмешательства по-прежнему может повторно переключать одно слово.
- Ввод следующего слова в очереди событий, отмена и ошибка исправления не оставляют запрет на чужом слове.
