# Отслеживание физического отпускания Shift через HID

Идея для обсуждения восстановления Shift после исправления, связанная с [непринятым предложением о долгом удержании Shift в задаче 5.3](tasks/5.3.md#непринятое-предложение-долгое-удержание-shift). Реализация и работоспособность на конкретных клавиатурах пока не подтверждены. Документ не меняет [текущий протокол 5.3](tasks/5.3.md#вызов-исправления-и-модификаторы) на основе эксперимента 101: исходные модификаторы не восстанавливаются.

## Проблема

Искусственное `Shift up`, записанное через исходное устройство evdev, меняет состояние клавиши в ядре. Если после этого пользователь действительно отпускает Shift, ядро может отфильтровать физическое отпускание как повторное: оно уже хранит состояние «отпущен».

Через evdev такое отфильтрованное событие не получить. Поэтому отсутствие `Shift up` в прочитанном потоке не доказывает, что пользователь продолжает держать кнопку. Восстановление нажатия по этому предположению может привести к залипанию.

## Идея

Для HID-клавиатур читать исходные отчёты через `/dev/hidrawN`. Эти отчёты позволяют наблюдать состояние, сообщаемое устройством, независимо от искусственно изменённого состояния evdev. По изменению соответствующих данных отчёта можно определить физическое отпускание Shift.

HID — стандарт взаимодействия с устройствами ввода. `hidraw` предоставляет исходные отчёты устройства, а evdev — события, полученные после обработки в подсистеме ввода. Для клавиатур без доступного HID-интерфейса этот способ не подходит.

## Время наблюдения

Постоянное чтение HID-отчётов не предполагается. Наблюдение требуется только на время переключения:

1. Заранее определить соответствие физических устройств evdev и hidraw, получить и разобрать описания формата HID-отчётов.
2. До искусственного отпускания модификаторов начать приём HID-отчётов и согласовать начальное состояние с наблюдаемым состоянием клавиш.
3. Во время исправления отслеживать физическое состояние Shift по HID-отчётам, даже если evdev не сообщает его отпускание.
4. Продолжать наблюдение до завершения восстановления и возврата прямого ввода. Точный протокол этой границы ещё требуется разработать: одной последней выборки состояния недостаточно, если сразу после неё пользователь отпускает Shift.
5. Завершить наблюдение после согласованного выхода из операции.

Начинать чтение только после искусственного `Shift up` нельзя: между этими действиями можно пропустить настоящее отпускание. Открытие hidraw само по себе также не гарантирует немедленного получения отчёта о текущем состоянии. Начальную синхронизацию и обработку очередей необходимо определить отдельно.

## Ожидаемая нагрузка

Значимая дополнительная нагрузка от чтения клавиатурных отчётов только во время переключения маловероятна. Это предварительная оценка, без измерений.

Чтение должно ожидать готовности данных через событийный механизм, без активного опроса в цикле. `hidraw` поддерживает блокирующее чтение до появления отчёта. Обнаружение устройств и разбор описаний отчётов следует выполнять заранее, чтобы не добавлять эту работу в момент переключения.

Основная ожидаемая сложность — согласование HID, evdev и границ захвата, а не производительность.

## Что ещё необходимо определить и проверить

- Соответствие hidraw и evdev для конкретных клавиатур, включая устройства с несколькими интерфейсами.
- Разбор форматов отчётов и различение левого и правого Shift.
- Получение достоверного начального состояния без потери изменений на границе начала наблюдения. API `HIDIOCGINPUT` позволяет запросить входной отчёт; пригодность запроса для конкретных устройств и его согласование с очередью требуют теста.
- Доставку HID-отчётов при захвате evdev и искусственных изменениях состояния через evdev.
- Протокол восстановления: состояние ядра и окружения должно соответствовать физическому состоянию, включая отпускание непосредственно перед восстановлением или во время выхода из захвата.
- Поведение при недоступности hidraw, отключении устройства или ошибке чтения. Не считать отсутствие отчётов подтверждением удержания Shift.
- Фактическую нагрузку и задержку на целевой системе.
