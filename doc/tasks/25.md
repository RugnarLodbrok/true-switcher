# Задача 25. Выделение `Interceptor` для захвата клавиатуры

## Цель

Вынести управление захватом клавиатур в отдельную сущность — `Interceptor`. Это рефакторинг существующего протокола [задачи 5.3](5.3.md): поведение переключения и сам протокол пока не меняем.

Рефакторинг готовит код к будущему упрощению протокола: для него предполагается написать новый `Interceptor`. Само упрощение в эту задачу не входит.

## Идея

`Interceptor` отвечает за вход в захват и выход из него. После успешного входа вызывающий код выполняет исправление между входом и выходом; само исправление не входит в обязанности `Interceptor`.

Использовать RAII: время жизни объекта захвата ограничивает период перехвата. Штатное завершение вызывается явно, поскольку выход может ожидать отпускания клавиш и возвращать ошибку. При досрочном выходе или ошибке `Drop` выполняет попытку аварийной очистки.

## Связь с обработкой ввода

`Interceptor<'a>` хранит `&'a mut Input` на время захвата. При входе, исправлении и выходе он использует `Input` для чтения и обработки общего потока событий, отслеживания состояния клавиш и реакции на `back_off`. Отдельно передавать очередь событий или итератор не требуется.

Пока существует `Interceptor`, вызывающий код не может обращаться к `Input` напрямую. Необходимые во время захвата операции предоставляются через `Interceptor`; точный набор методов предстоит определить при реализации.

### Владение состоянием и разделение методов

`Interceptor` владеет состоянием протокола: `recording`, `repair`, `repair_prepared` и `is_captured`. Эти поля объединяются во внутренний `InterceptionState`.

В `Input` остаются устройства, физическое состояние клавиш, очередь событий, история, раскладка, распознавание запросов и `back_off`. Фактический захват каждого устройства по-прежнему отслеживается самим устройством через `device.is_grabbed()`: общий `is_captured` не заменяет это состояние, в том числе при частичном захвате.

Во время входа, исправления и выхода `Interceptor` передаёт в методы чтения и обработки событий `Input` временную изменяемую ссылку на `InterceptionState`. В обычном режиме контекст отсутствует. Ссылка передаётся по цепочке вызовов, включая ожидание событий, и не сохраняется в `Input`. Обратная ссылка на `Interceptor` и разделяемое владение через `Rc<RefCell<_>>` не требуются.

Условный вид вызовов:

```rust
self.input.process_available_events(Some(&mut self.state))?;  // Во время работы Interceptor
input.process_available_events(None)?;  // Обычный режим
```

`Input` записывает обработанные нажатия в `recording` переданного контекста и учитывает `is_captured` при обработке истории, раскладки и отмены исправления. Полями `repair` и `repair_prepared` управляет `Interceptor`; обработчику событий они не нужны.

Разделение методов:

| В `Interceptor` | В `Input` |
| --- | --- |
| Протокол `enter`, `leave` → `finish`, `rollback` | Чтение и ожидание событий, обработка событий и таймеров |
| Начало и завершение записи нажатий | Запись обработанного нажатия в переданный контекст |
| Порядок захвата, отпускания и восстановления клавиш | Операции над устройствами: `grab`, `ungrab`, `write_source`, отпускание модификаторов и lock-клавиш |
| Решение, когда снять снимок состояния | Чтение состояния устройств и обновление отслеживаемых клавиш |

`snapshot` может одновременно обновлять физическое состояние клавиш и дополнять `recording`, получая тот же контекст. Точные сигнатуры внутренних методов определяются при реализации.

### Разделение очистки

Весь протокол завершения перехвата принадлежит `Interceptor`. Из текущего `Input::drop()` в `Interceptor::drop()` переходят следующие обязанности:

- Завершение незаконченной записи: обработка доступных событий, снимок состояния и перенос записанных нажатий в `repair`.
- Откат незавершённого входа через `rollback`.
- Отпускание модификаторов при активном захвате.
- Снятие захвата устройств и отпускание lock-клавиш.

Этот перечень определяет обязанности, а не новый порядок действий: порядок существующего протокола сохраняется. Операции над устройствами остаются методами `Input`; `Interceptor` управляет их вызовами.

`Interceptor` создаётся до первого действия, требующего отката. Ошибка во время входа, включая частичный захват устройств, приводит к уничтожению локального `Interceptor`, который выполняет аварийную очистку через ещё живой `Input`. Заимствование `&mut Input` обеспечивает нужный порядок жизни объектов.

При ошибке аварийной очистки `Interceptor::drop()` записывает её в журнал и продолжает остальные доступные действия. `Input::drop()` не запускает протокол повторно и не хранит состояние незавершённого восстановления. Если другой очистки у `Input` нет, явная реализация `Drop` удаляется: поля и устройства уничтожаются обычным образом. Закрытие дескрипторов снимает оставшийся захват на уровне ОС, но не заменяет восстановление клавиш в `Interceptor`.

### Фазы и прогресс очистки

`Interceptor` отдельно отслеживает фазу протокола и прогресс очистки. Фаза представлена внутренним enum:

| Фаза | Действия `Drop` |
| --- | --- |
| `Entering` | Собрать незавершённую запись и выполнить откат незавершённого входа |
| `Captured` | Аварийно завершить принятый захват |
| `Finishing` | Выполнить оставшуюся аварийную очистку после ошибки штатного завершения |
| `Finished` | Ничего не делать |

`finish` потребляет объект:

```rust
pub fn finish(mut self) -> io::Result<()>
```

До первого действия `finish()` фаза меняется на `Finishing`. Только после успешного завершения всей очистки устанавливается `Finished`, поэтому последующий `Drop` ничего не делает. При ошибке `finish()` автоматически вызывается `Drop`, который пытается выполнить оставшуюся очистку. Вызывающий код получает исходную ошибку `finish()`; ошибки аварийной очистки записываются в журнал. После вызова `finish()` использовать объект перехвата больше нельзя.

После успешного отката отменённого входа устанавливается `Finished`. Если откат нужен для повторной попытки входа, после его успеха объект остаётся в `Entering`, а состояние попытки сбрасывается. При ошибке отката объект не помечается завершённым.

Прогресс очистки учитывается независимо от фазы:

- `device.is_grabbed()` определяет, какие устройства ещё требуют снятия захвата. Успешно освобождённые устройства повторно не освобождаются.
- `repair` и `repair_prepared` отражают прогресс восстановления нажатий. Успешно восстановленные клавиши удаляются из наборов.
- Для остальных этапов, завершение которых нельзя определить по этим данным, сохраняются необходимые отметки. Точный набор отметок определяется при реализации по последовательности очистки.

Журнал каждого успешного системного вызова не требуется. Безопасное повторное отпускание lock-клавиш после частичной ошибки допустимо. Очистка не должна запускать весь протокол заново или повторять завершённое восстановление нажатий.

`finish()` может ожидать отпускания клавиш. `Drop` не ждёт действий пользователя: выполняет аварийную очистку, продолжает доступные действия после ошибок и записывает ошибки в журнал. Штатное завершение и аварийная очистка используют общие операции и данные прогресса, но имеют разный порядок управления.

### Подготовка и результат входа

`Correction` создаётся после успешного входа в захват из актуального состояния `Input`, доступного через `Interceptor`. Предварительно создавать `Correction` до входа не требуется: во время входа обработка событий может изменить историю. Само создание `Correction` остаётся обязанностью вызывающего кода.

`Interceptor::enter()` возвращает `io::Result<Option<Self>>`: `Some` означает успешный вход, `None` — штатную отмену входа, в том числе при `back_off`. Перед возвратом `Ok(None)` выполняется откат частичного входа; ошибка отката возвращается как `Err`. `Drop` остаётся страховкой для аварийной очистки.

Пример использования внутри цикла обработки запросов; `perform_correction` условно обозначает подготовку `Correction` и выполнение исправления:

```rust
let Some(mut interception) = Interceptor::enter(&mut input)? else {
    continue;  // Вход отменён, в том числе при back_off; возвращаемся к ожиданию запроса
};

perform_correction(&mut interception)?;  // Correction создаётся после успешного входа
interception.finish()?;  // Штатный выход с ожиданием отпускания клавиш
```

Ошибка возможна и во время входа, до получения готового объекта захвата. Частично выполненный вход тоже должен быть защищён очисткой, включая случай частичного захвата устройств.

## Предварительная иллюстрация чтения событий и отмены входа

Ниже — предварительный вид `Interceptor::enter()`, иллюстрация взаимодействия, а не требование к реализации. Названия вспомогательных методов условные; детали состояния и протокола входа опущены.

`Interceptor` вызывает методы `Input`, а `Input` сам читает и обрабатывает события, обновляет состояние клавиш и обнаруживает `back_off`. Обнаружение `back_off` и выход из `enter()` происходят в разных строках: `Input` сбрасывает `pending`, затем `Interceptor` проверяет состояние и откатывает вход в предусмотренной протоколом точке.

```rust
struct Interceptor<'a> {
    input: &'a mut Input,
    state: InterceptionState,
    // Состояние частичного входа для отката и Drop опущено
}

impl<'a> Interceptor<'a> {
    fn enter(input: &'a mut Input) -> io::Result<Option<Self>> {
        let mut interception = Self {
            input,
            state: InterceptionState::default(),
        };

        loop {
            // Input обрабатывает события и таймеры во время ожидания.
            // При back_off сбрасывает pending, и wait_ordinary возвращает false.
            if !interception.input.wait_ordinary(Some(&mut interception.state))? {  // Ошибка чтения или обработки событий → Err
                interception.rollback()?;  // Ошибка отката отменённого входа → Err
                return Ok(None);  // Вход отменён, в том числе при back_off
            }

            interception.begin_recording();
            interception.release_locks()?;  // Ошибка отпускания lock-клавиш → Err
            interception.release_modifiers()?;  // Ошибка отпускания модификаторов → Err
            interception.release_switch_key()?;  // Ошибка отпускания клавиши переключения → Err

            interception.input.process_available_events(Some(&mut interception.state))?;  // Ошибка чтения или обработки → Err; Input может обнаружить back_off
            interception.grab()?;  // Ошибка захвата устройства, включая частичный захват → Err
            interception.input.process_available_events(Some(&mut interception.state))?;  // Ошибка чтения или обработки → Err; Input может обнаружить back_off
            interception.snapshot()?;  // Ошибка чтения состояния клавиш устройства → Err
            interception.input.process_available_events(Some(&mut interception.state))?;  // Ошибка чтения или обработки → Err; Input может обнаружить back_off

            let presses = interception.finish_recording();

            // Проверяем отмену после обработки событий во время входа.
            // В частности, back_off мог сбросить pending.
            if interception.input.pending.is_none() {
                interception.prepare_repair(presses);
                interception.rollback()?;  // Ошибка отката отменённого входа → Err
                return Ok(None);  // Вход в перехват отменён
            }

            if presses.is_empty() {
                interception.mark_captured();
                return Ok(Some(interception));
            }

            interception.prepare_repair(presses);
            interception.rollback()?;  // Ошибка отката неудачной попытки входа → Err
            // Во время входа были нажатия — повторяем попытку
        }
    }
}
```

Каждый `?` при ошибке возвращает `Err` из `enter()`, после чего `Drop` локального объекта `Interceptor` выполняет попытку аварийной очистки. Сам `back_off` означает штатную отмену входа через `Ok(None)`, если откат завершился успешно.
