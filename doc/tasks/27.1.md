# Задача 27.1. Автосвич по логарифму отношения правдоподобий

## Цель

Сравнивать частоты двух префиксов, полученных из одних и тех же нажатий в текущей и целевой раскладках. Новый `score` должен расти, когда очередное нажатие усиливает свидетельство в пользу целевой раскладки, даже если абсолютные частоты обоих префиксов снизились.

Конфигурация требует ровно двух записей `[[dict]]` с разными `target`. Ноль, одна или более двух записей — ошибка конфигурации. Режим с одним словарём отложен в [задачу 27.2](27.2.md).

## Решение о переключении

`DictionaryAutoSwitch` оценивает одни и те же нажатия для направления из текущей раскладки в альтернативную. Единица `score` — бит. Словарный запрос возникает при строгом сравнении

```text
score > alternative.threshold
```

Каждая запись `[[dict]]` задаёт собственный `threshold` для переключения **на** её `target`. Пример с условными значениями:

```toml
[[dict]]
target = "us"
file = "dictionaries/en_full.txt"
threshold = 5.0

[[dict]]
target = "ru"
file = "dictionaries/ru_full.txt"
threshold = 7.0
```

Для `ru → us` отношение правдоподобий должно превысить 32, для `us → ru` — 128. При точном равенстве порогу ввод продолжается в текущей раскладке. В новой конфигурации `threshold` заменяет оба поля `slip` и `grip`. Порог задаётся конечным положительным числом в битах.

Миграция существующих конфигов с `slip` и `grip` не требуется.

### Два словаря

Для каждого словаря `P(prefix)` равна сумме частот слов с этим префиксом, делённой на сумму частот всех принятых записей этого словаря. Для положительных вероятностей:

```text
score = log₂(P_alt(prefix_alt) / P_current(prefix_current))
```

| Частота в текущем словаре | Частота в целевом словаре | Словарное решение |
|---|---|---|
| Положительная | Положительная | Вычислить `score` и сравнить с порогом цели |
| Ноль | Положительная | Запросить свич даже при одном вхождении в целевом словаре. Оценка равна `+∞` |
| Любая | Ноль | Оставить текущую раскладку, в том числе при двух нулях |

Например, при отношении 4 оценка равна 2 битам. Если следующее нажатие уменьшает частоту альтернативного префикса вдвое, а текущего — в 32 раза, отношение вырастает до 64, оценка — до 6 бит. При переключении на `us` с порогом из примера запрос возникает именно на этом нажатии.

## Логирование

Удалить текущее trace-сообщение `Dictionary prefix scores`. При включённом словарном автосвиче каждое текстовое нажатие, добавившее `WordStroke` в `Word`, пишет в trace-лог одну строку с новым `score` для обновлённого префикса. Запись выводится независимо от результата переключения. Пробел, Backspace и другие события без добавления `WordStroke` пропускаются.

```text
dict switch score: +3.43
```

Конечный `score` выводится с явным знаком, десятичной точкой и ровно двумя цифрами после неё, включая ноль (`+0.00`). Округление применяется только при выводе. Для бесконечных значений использовать `+inf` и `-inf`, для двух нулевых частот или недоступной оценки — `unavailable`.

## Интеграция и критерии готовности

- Применяются порядок обработки ввода и ограничения из [задачи 27](27.md), включая приоритет regex, восстановление префиксов по Backspace и блокировку повторного исправления слова. Ошибка преобразования XKB делает требуемую оценку недоступной.
- Тест с двумя словарями воспроизводит рост оценки с 2 до 6 бит при убывании обеих частот. Тесты обоих направлений различают пороги источника и цели и покрывают точное равенство целевому порогу.
- Тесты конфигурации принимают два корректных словаря с разными `target` и проверяют ошибку для нуля, одного и трёх словарей, а также для двух словарей с одинаковым `target`.
- Для двух словарей тесты покрывают три случая с нулями. Ноль в текущем словаре и одно вхождение в целевом вызывают свич. Ноль только в целевом словаре и два нуля сохраняют текущую раскладку.
- Тест логирования проверяет точный формат сообщения для каждого введённого символа слова, включая префикс ниже порога, и отсутствие сообщения при пробеле и Backspace.
