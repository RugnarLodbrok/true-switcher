# Задача 27. Автосвич по словарям

Статус: реализация и автоматические тесты готовы. Ручные тесты в KDE Plasma ожидаются.

[Задача 27.1](27.1.md) заменяет описанные ниже формулу оценки, пороги, требования к количеству словарей и флаги включения автосвича.

## Цель и границы

Исправлять ввод в неверной раскладке до завершения слова, используя частоты возможных продолжений в одном или двух словарях. Проверка выполняется после каждого текстового нажатия, добавляющего запись в `Word`; ждать пробела или целого словарного слова не нужно.

Словарный автосвич поддерживает до двух настроенных раскладок KDE. Словарная эвристика рассматривает не более одной альтернативы.

Словарная эвристика дополняет существующие regex-паттерны. Приоритет остаётся у regex.

## Поведение до реализации

По коду на момент проработки:

- `Input::process_text_event` обновляет `History` и запрашивает цель у `AutoSwitchRules` после текстовой клавиши и первого пробела за словом.
- `AutoSwitchRules::target` преобразует нажатия в целевые раскладки и выбирает первое совпавшее regex-правило.
- `Word` хранит нажатия с раскладками и количество завершающих пробелов. Пунктуация входит в текущее слово; переход к следующему слову происходит при вводе текста после пробела.
- После ручного или автоматического исправления `History` блокирует дальнейший автосвич текущего слова. Эта блокировка сохраняется для словарного автосвича.
- Словарной проверки в текущем коде нет.

## Словарь и trie

Текстовый файл словаря использует формат [FrequencyWords](https://github.com/hermitdave/FrequencyWords). Каждая строка содержит слово и число его вхождений в исходном корпусе, разделённые пробелом.

Проектируемый компонент `DictionaryTrie` — trie одного языка, используемый для поиска префиксов и получения их суммарных частот. Это имя компонента в спецификации; окончательное размещение в коде пока не выбрано.

Для каждого узла `DictionaryTrie` хранится сумма частот всех слов, начинающихся с соответствующего префикса. Конец слова может находиться во внутреннем узле, поэтому сумма включает собственную частоту слова и суммы дочерних узлов. Например, узел `кот` учитывает и слово `кот`, и продолжение `коты`.

После нового символа поиск может продолжаться из текущего узла, сужая множество кандидатов. Если префикса нет, его частота равна нулю. Отсутствие законченного слова при наличии продолжений не обнуляет частоту.

Для поиска текст приводится к lowercase. Исправление сохраняет исходный регистр ввода.

При загрузке пропускаются записи со словами, содержащими хотя бы одну заглавную букву. Повторяющиеся слова среди оставшихся записей считаются ошибкой конфигурации.

### Состояние поиска в истории

Каждый `Word` хранит стек состояний поиска для каждого `DictionaryTrie`. Состояние хранит индекс узла соответствующего trie, отметку отсутствующего префикса или отметку ошибки преобразования. Сами деревья остаются общими и неизменяемыми.

- При добавлении записи `WordStroke` поиск продолжается из текущего состояния каждого trie, а результат добавляется в соответствующий стек. Состояния привязаны к нажатиям, а не к отдельным символам преобразованного текста.
- При удалении записи через Backspace последнее состояние удаляется из каждого стека. Для пустого префикса исходной позицией служит корень trie.
- Отметки отсутствующего префикса также сохраняются для каждого нажатия. Например, из `cat##` первый Backspace восстанавливает отсутствие префикса `cat#`, второй — узел `cat`.
- Ошибка преобразования XKB сохраняется отдельным состоянием стека соответствующей раскладки. Пока ошибочное нажатие входит в префикс, оценка для него недоступна. Backspace восстанавливает предыдущее состояние стека.
- Добавление и удаление завершающих пробелов не меняет состояния поиска.
- При восстановлении предыдущего слова используются сохранённые в нём стеки.

Состояния закреплены за конкретными словарями, независимо от того, какая раскладка сейчас текущая. Обратные переходы к родительским узлам trie для Backspace не требуются.

Backspace никогда не вызывает автосвич — ни regex, ни словарный. Он восстанавливает состояние поиска и отменяет ожидающий автоматический запрос. Словарная проверка возобновляется при следующем текстовом нажатии.

### Представление в памяти

`DictionaryTrie` строится в памяти при запуске из исходного текстового файла словаря. После построения дерево неизменяемое.

Выбрано единое представление переходов без отдельного случая для единственного дочернего узла:

- Узлы хранятся в общем массиве. Каждый узел содержит сумму частот и описание диапазона своих исходящих переходов.
- Переходы хранятся в другом общем массиве. Каждый переход содержит символ и индекс дочернего узла.
- Переходы одного узла занимают непрерывный диапазон и отсортированы по символу.
- Узлу без переходов соответствует пустой диапазон. Для одного перехода используется диапазон длиной один, без хранения перехода прямо в узле.
- Для любого размера диапазона используется binary search. Единый способ поиска выбран ради простоты кода; порог переключения на линейный поиск не вводится.
- Отдельные `Vec` или `HashMap` для каждого узла не требуются.

Radix tree со сжатием цепочек обсуждался, но в выбранное представление не входит. Способ построения общих массивов пока не закреплён: построение непосредственно из отсортированных записей и уплотнение временного дерева остаются вариантами, а не принятыми решениями.

## Нормализованная оценка и пороги

Для каждого языка вычисляется оценка:

```text
score(prefix) = сумма частот слов с этим префиксом
                / сумма частот всех слов соответствующего словаря
```

Общая сумма частот для нормализации вычисляется по записям соответствующего словаря, оставшимся после фильтрации.

Оценка относится к префиксу, а не только к законченному слову. При отсутствии префикса `score = 0`.

У каждого словаря своя пара порогов:

- `slip` — нижняя граница: ниже неё словарь текущей раскладки «отпускает» ввод.
- `grip` — верхняя граница: выше неё словарь альтернативной раскладки «подхватывает» ввод.

Условие словарного автосвича для двух словарей:

```text
score(current_prefix) < current.slip
и
score(alternative_prefix) > alternative.grip
```

Здесь `current` и `alternative` обозначают словари текущей и альтернативной раскладок. При обратном направлении переключения словари меняются ролями: используется `slip` нового текущего словаря и `grip` нового альтернативного.

Если настроен один словарь и его `target` отличается от текущей раскладки, для свича в эту цель достаточно `score(alternative_prefix) > alternative.grip`. Условие по `slip` пропускается. Если его `target` совпадает с текущей раскладкой, словарный свич не выполняется.

Значения порогов пользователь самостоятельно задаёт и подбирает в конфигурации. Значения разных словарей могут различаться. Подбор готовых значений, согласование набора примеров и допустимой частоты ложных переключений в эту задачу не входят.

`slip` и `grip` задаются в нормализованных единицах, соответствующих `score`. Допустимы конечные числа от `0` до `1` включительно.

Нормализация устраняет влияние общего масштаба частот. Состав, покрытие и распределение частот словаря продолжают влиять на оценки; независимость поведения от этих свойств не гарантируется.

Дополнительные условия в виде минимальной длины префикса или отношения двух оценок не согласованы и в принятое условие не входят.

## Порядок принятия решения

Проектируемый компонент `DictionaryAutoSwitch` — словарная эвристика, которая использует настроенные `DictionaryTrie` и пороги для выбора альтернативной раскладки. Итоговый выбор между regex и словарной эвристикой должен соблюдать следующий порядок:

1. Применить существующие ограничения автосвича, включая блокировку текущего слова после исправления.
2. Проверить regex-паттерны в существующем порядке. Если regex выбрал цель, использовать её, независимо от словарной оценки.
3. Если regex не выбрал цель, нажатие добавило `WordStroke` и есть альтернативная цель, проверить представления всего текущего `Word` без завершающих пробелов по словарям, участвующим в решении. При ошибке преобразования XKB в любой раскладке, для которой требуется оценка, пропустить словарное решение для этого префикса. Нулевая оценка применяется только к успешно преобразованному префиксу, отсутствующему в trie.
4. При выполнении применимых пороговых условий запросить исправление в альтернативную раскладку, используя существующий механизм коррекции.
5. После успешного автосвича заблокировать дальнейшие автоматические исправления текущего слова независимо от источника решения: regex или словарь.

Это порядок выбора цели. Фактическое исправление выполняется существующим механизмом с его условиями готовности; словарная проверка не должна обходить его.

### Границы слова и состав ввода

Границы слова остаются ровно такими, как в текущем коде `History` и `Word`. Цифры и пунктуация входят в тот же `Word`; отдельные буквенные части из него не выделяются. Например, `hello123`, `user-name`, `/start` и `привет,мир` проверяются целиком, каждый как один префикс.

Отдельного ограничения «только буквенный ввод» нет: проверка буквенности, фильтрация символов и отключение словарного поиска из-за цифры или пунктуации не требуются. Состав допустимых префиксов определяется самим trie. Если перехода по очередному символу нет, оценка соответствующей раскладки становится нулевой по общему правилу. Если такой префикс есть в словаре, используется его обычная оценка.

Представления нажатий в двух раскладках оцениваются независимо: символ может отсутствовать в trie одной раскладки, а в другой соответствующее нажатие может дать существующий префикс. Нулевая оценка одной раскладки сама по себе не запрещает автосвич в другую.

### Dead keys

Если XKB определяет нажатие в исходной раскладке как dead key, например `dead_acute` в `us(intl)`, ожидающий автоматический запрос отменяется. Для этого `Word` блокируются ручное исправление и оба вида автосвича. Backspace сам по себе не снимает блокировку этого слова, поскольку одно удаление в приложении может затронуть результат нескольких нажатий.

Если воспроизведение нажатий в целевой раскладке задействует dead key, исправление в эту цель также блокируется. Поддержка композиции описана в [задаче 30](30.md).

При блокировке ручного исправления из-за dead key клавиша исправления оставляет текущую раскладку и текст как есть.

### Первый пробел и ожидающее исправление

Первый пробел по-прежнему запускает regex-проверку при соблюдении существующих ограничений автосвича. Словарная проверка выполняется только при добавлении `WordStroke`.

- Если regex на первом пробеле выбрал цель, использовать её, в том числе взамен ожидающей словарной цели.
- Если regex на первом пробеле не выбрал цель, сохранить ожидающий словарный запрос для этого `Word`, если он есть. Ожидающий regex-запрос в этом случае по-прежнему отменяется.

После успешного захвата клавиатуры автоматическая коррекция берёт актуальные `Word` и цель с учётом событий, обработанных до захвата. Если за это время первый пробел вошёл в `Word`, коррекция стирает и воспроизводит его вместе со словом. Если запрос был отменён до захвата, коррекция не запускается.

### Блокировка после исправления

Повторный автосвич одного слова запрещён, в том числе при переходе между разными источниками решения:

- после regex-свича словарь больше не исправляет это слово;
- после словарного свича regex больше не исправляет это слово;
- после ручного исправления словарная проверка также заблокирована.

Существующие правила снятия блокировки `History` сохраняются: создание следующего слова, полное удаление текущего слова или сброс истории. Консервативные пороги не заменяют эту блокировку.

## Конфигурация

Словарный автосвич управляется существующим флагом `auto_switch` и наличием словарей в конфигурации. Отдельный флаг включения не вводится.

Пороги `slip` и `grip` задаются в записи каждого словаря и относятся к его собственной нормализованной оценке.

Словари задаются массивом TOML-таблиц `[[dict]]`. Каждый блок описывает отдельный словарь со своими `target`, `file`, `slip` и `grip`.

Допускается от нуля до двух записей `[[dict]]` с уникальными `target`. При отсутствии записей словарный автосвич выключен.

`target` — код раскладки, соответствующей словарю, например `us` для английского языка или `ru` для русского. Он проверяется через тот же `kde::target_layout`, что и `switch_rules.target`. Код должен присутствовать в реестре XKB и в списке настроенных раскладок KDE и сопоставляться с записью в `kxkbrc`.

Файлы словарей находятся в папке рядом с конфигом. Поле `file` задаёт путь относительно директории, содержащей `config.toml`. Например, `file = "dictionaries/en_full.txt"` при конфиге `~/.config/true-switcher/config.toml` указывает на `~/.config/true-switcher/dictionaries/en_full.txt`. Текущая рабочая директория приложения на разрешение пути не влияет.

Пример записи словаря:

```toml
[[dict]]
target = "us"
file = "dictionaries/en_full.txt"
grip = 0.001
slip = 0.000001
```

Значения порогов в примере не являются подобранными рабочими значениями.

Отсутствие или повреждение файла словаря, повторяющиеся слова среди оставшихся записей, нулевая сумма частот после фильтрации, недопустимые `slip` или `grip`, невалидный или повторяющийся `target` и более двух записей `[[dict]]` считаются ошибками конфигурации. Для включённого словарного автосвича более двух настроенных раскладок KDE также считаются ошибкой конфигурации. Приложение использует существующий режим ошибки конфигурации с красным значком в трее.

## Критерии готовности

- Суммы узлов включают частоты слов, заканчивающихся как в листьях, так и во внутренних узлах.
- Неизменяемый trie хранится в общих массивах узлов и переходов. Диапазоны переходов отсортированы, одиночный переход не имеет отдельного представления; поиск перехода выполняется через binary search для любого размера диапазона.
- Поиск работает по lowercase, отсутствие префикса даёт нулевую оценку, наличие только продолжений даёт их суммарную оценку.
- Стеки состояний каждого trie сохраняются в `Word` по нажатиям. Backspace восстанавливает предыдущее состояние, включая возврат из отсутствующего префикса к существующему; при возврате к предыдущему слову используются его сохранённые стеки.
- Backspace никогда не вызывает автосвич и отменяет ожидающий автоматический запрос.
- При ошибке XKB в любой раскладке, для которой требуется словарная оценка, решение пропускается. Backspace восстанавливает предыдущее состояние поиска.
- Dead key в исходном вводе отменяет ожидающий автосвич и блокирует ручное и автоматическое исправление слова. Исправление в цель, в которой нажатия задействуют dead key, тоже блокируется. При блокировке ручного исправления текст и раскладка остаются прежними.
- Записи со словами, содержащими заглавные буквы, пропускаются при загрузке. Оценки нормализуются по сумме частот оставшихся записей соответствующего словаря. Пропорциональное масштабирование оставшихся частот не меняет результат.
- При двух словарях применяются строгие сравнения `score(current_prefix) < current.slip` и `score(alternative_prefix) > alternative.grip`. При обратном направлении словари меняются ролями.
- При одном словаре свич возможен только в его `target` и требует сравнения `score(alternative_prefix) > alternative.grip`. Когда эта раскладка уже текущая, словарного запроса нет.
- Словарный автосвич включается существующим флагом `auto_switch` при наличии словарей в конфигурации.
- Конфигурация принимает от нуля до двух словарей с уникальными кодами. Каждый `target` проходит ту же валидацию, что и `switch_rules.target`.
- Подходящее слово может быть исправлено до ввода разделителя; исходный регистр сохраняется.
- Границы `Word` сохраняются. Цифры и пунктуация проверяются в составе всего слова без отдельного фильтра буквенности; отсутствующий префикс даёт нулевую оценку только в соответствующем trie.
- При конфликте на одном вводе regex имеет приоритет.
- Автоматические тесты покрывают первый пробел между созданием словарного запроса и захватом клавиатуры. При совпадении regex коррекция использует его цель, без совпадения сохраняет словарную цель. В обоих случаях коррекция использует актуальный `Word` и сохраняет пробел.
- Любое успешное исправление блокирует последующие автосвичи текущего слова; существующее снятие блокировки сохраняется.
- Пути `file` разрешаются относительно директории конфига независимо от текущей рабочей директории приложения, в том числе при запуске без установки.
- Ошибки словарной конфигурации переводят приложение в существующий режим ошибки конфигурации с красным значком в трее. При включённом словарном автосвиче это относится и к трём или более раскладкам KDE.
- Автоматические тесты покрывают вычисление оценок, выбор цели, приоритет regex и блокировку. Ручные тесты проверяют раннее исправление в KDE Plasma и продолжение ввода после него.
- Пороги каждого словаря читаются из конфигурации. Значения `0` и `1` принимаются. Значения вне диапазона, `NaN` и бесконечности дают ошибку конфигурации. Пороги пользователь подбирает самостоятельно.
