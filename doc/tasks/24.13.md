# Задача 24.13. Разделение модели раскладки, XKB и интеграции KDE

## Статус

Предложение для обсуждения, реализация не начата. Задача вынесена из пункта 13 [задачи 24](24.md). Оформление задачи не означает согласования всех деталей интерфейсов.

**Комментарий пользователя из задачи 24:** надо обсуждать.

## Проблема

В `src/layout.rs` объединены разные обязанности:

- `Layout` хранит параметры раскладки: `name`, `variant`, `model`, `options`.
- `Layout::text` преобразует последовательность `Stroke` в текст через XKB.
- `current_layout`, `target_layout` и `layout_index` обращаются к KDE через D-Bus, читают `kxkbrc` и сопоставляют раскладки с конфигурацией. `target_layout` также проверяет идентификатор по реестру XKB.
- `LayoutTracker` наблюдает за изменениями и публикует сообщения в очередь ввода.

При этом переключение находится в `environment::KdePlasma` в `src/environment.rs` и выполняется через внешний `qdbus`. Для переключения по имени `KdePlasma::switch_to_layout` обращается обратно в `layout::layout_index`.

Интеграция KDE распределена между двумя модулями, а преобразование текста связано с модулем, содержащим D-Bus и конфигурацию рабочего стола. Название `environment` слишком широко для его текущей ответственности.

## Предлагаемые границы

### `layout`: описание раскладки

Модуль `layout` сохраняет тип `Layout` с параметрами `name`, `variant`, `model`, `options`. Он не читает состояние KDE и его конфигурацию.

`Layout` представляет снимок параметров. Сохранённые в `WordStroke.layout` значения используются для преобразования истории независимо от текущей раскладки KDE. Неизвестная раскладка по-прежнему представляется через `Option<Arc<Layout>>`.

Согласовано: точкой входа преобразования остаётся метод `Layout`, переименованный из `text` в `to_text`. Потребители вызывают `layout.to_text(strokes)`; отдельный преобразователь им не передаётся.

Будущий кеш скомпилированной карты XKB принадлежит объекту `Layout` и соответствует его параметрам. Это внутреннее состояние, которое не должно влиять на сравнение раскладок. При проектировании кеша необходимо обеспечить соответствие карты параметрам при их изменении либо исключить изменение параметров после создания объекта.

### `xkb`: преобразование клавиш в текст

Новый модуль `xkb` содержит реализацию преобразования последовательности `Stroke` по заданному `Layout`: создание контекста и карты, обработку Shift, получение и проверку символов. Преобразование не обращается к KDE и не запрашивает текущую раскладку.

`Layout::to_text` делегирует реализацию модулю `xkb`, сохраняя владение кешем за объектом `Layout`. Модуль `xkb` может определять внутренний тип кеша и операции над ним.

Согласовано: проверка идентификатора раскладки по реестру XKB находится в `xkb`. Модуль читает и разбирает реестр и сообщает, известен ли указанный идентификатор. Эта проверка не гарантирует успешную компиляцию карты с заданными `variant`, `model` и `options`; ошибки компиляции обрабатываются отдельно.

Кеширование не входит в реализацию 24.13 и остаётся отдельной задачей 24.1 из пункта 3 задачи 24. В ней предстоит выбрать способ инициализации кеша и его использования из потоков ввода и статистики, проверить ограничения потоковой передачи объектов используемой XKB-библиотеки и совместимость хранения с `Arc<Layout>`. Само наличие `Arc` или добавление блокировки не доказывает допустимость передачи XKB-объектов между потоками. Эти вопросы не блокируют разделение модулей без добавления кеша.

### `kde`: интеграция с KDE

Новый модуль `kde` объединяет `KdePlasma`, `LayoutTracker` и связанные функции интеграции:

- Чтение `kxkbrc` и сопоставление параметров с раскладками, возвращаемыми KDE.
- Получение текущей раскладки и разрешение целевой раскладки.
- Поиск индекса и переключение на выбранную или следующую раскладку.
- Наблюдение за изменениями, восстановление подключения и публикацию сообщений.

Модуль возвращает снимки `Layout`, но не преобразует слова в текст. Поиск индекса для переключения становится внутренней деталью KDE-интеграции. При разрешении цели `kde` вызывает проверку идентификатора из `xkb`, затем проверяет наличие раскладки в конфигурации KDE и получает её параметры. Проверка по реестру не добавляется к чтению текущего состояния.

Объединение в модуле не требует превращать все функции и `LayoutTracker` в один большой объект. Универсальный интерфейс для нескольких рабочих столов без конкретного потребителя не вводится.

## Ошибки преобразования

Первая часть пункта 16 задачи 24 входит в 24.13. `Layout::to_text` и `Word::text` возвращают `Result` вместо `Option`, позволяя различать причины неуспешного преобразования. Согласованы следующие причины; названия вариантов приведены как рабочие обозначения:

| Причина | Значение |
| --- | --- |
| `UnknownLayout` | У нажатия в `WordStroke` отсутствует сохранённая раскладка. Возникает при преобразовании `Word::text`; преобразование физических нажатий в явно заданную целевую раскладку не требует исходной раскладки. |
| `InvalidParameter` | В `name`, `variant`, `model` или `options` есть нулевой байт. Ошибка указывает некорректное поле. |
| `KeymapCompilationFailed` | XKB не смог скомпилировать карту по параметрам `Layout`. Проверка имени по реестру не исключает эту ошибку. |
| `ShiftUnavailable` | Для нажатия с `shift` невозможно получить применимую маску Shift. |
| `NoTextForKey` | Сохранённое в слове нажатие не дало текста в выбранной раскладке. Преобразование завершается ошибкой; нажатие не пропускается. |
| `ControlCharacter` | Полученный текст содержит управляющий символ, запрещённый текущим преобразованием слова. |

Согласованное правило: если сохранённое в слове нажатие не дало текста, возвращается `NoTextForKey` и ошибка логируется. Пустой результат XKB не считается основанием для пропуска нажатия.

Основание по текущему коду: `History::process` добавляет в `Word.entries` только клавиши, разрешённые `history::is_text_key`: физические клавиши буквенных рядов, цифр и пунктуации, включая `KEY_102ND`. Shift, функциональные клавиши и стрелки в `Word.entries` не записываются. Пробелы учитываются отдельно через `trailing_spaces`, Backspace удаляет нажатие. Поэтому отдельная фильтрация нетекстовых клавиш в преобразователе для текущего пути ввода не требуется.

Разрешённая физическая клавиша может оказаться dead key в выбранной раскладке. Текущий преобразователь не использует Compose для обработки таких последовательностей; пустой результат для такого нажатия также приводит к `NoTextForKey`. Поддержка Compose этой задачей не добавляется. Это сохраняет текущее поведение без незаметной потери части слова. См. [документацию XKB о Compose и dead keys](https://xkbcommon.org/doc/current/group__compose.html).

Ошибка нарушения соответствия отдельных массивов нажатий и раскладок не вводится: после изменения модели эти данные хранятся вместе в `WordStroke`.

### Обработка потребителями и логирование

- При ошибке преобразования одной целевой раскладки `AutoSwitchRules::target` продолжает следующие правила, сохраняя их порядок. Частичный текст не используется для сопоставления.
- При ошибке преобразования для статистики связанная запись пропускается целиком. Частичный текст не сохраняется. Результат исправления не зависит от этой ошибки.
- Каждая возникшая ошибка преобразования логируется, включая `UnknownLayout`, `NoTextForKey` и `ControlCharacter`. Молчаливое подавление и ограничение частоты, скрывающее отдельные ошибки, не применяются.
- Одно возникновение ошибки логируется один раз, без повторного сообщения при передаче между `xkb`, `Layout` и `Word`. Для диагностики указываются причина и относящийся к ней контекст: параметры раскладки, некорректное поле или код клавиши. Вывод полного текста слова для этого не требуется.

## Поведение, которое нужно сохранить

- Переключение через `qdbus`, включая поиск исполняемого файла и обработку ошибок. Замена транспорта этой задачей не согласована; чтение и наблюдение могут продолжать использовать `zbus`.
- Порядок публикации `LayoutChanged` и `CorrectionFinished`, обеспечиваемый общим `LayoutTracker::observation`. Перенос кода не должен позволить устаревшему наблюдению перезаписать результат завершённого исправления.
- Повторное чтение состояния при сигналах KDE, обработку смены владельца D-Bus, потерю известной раскладки при сбое и восстановление наблюдения.
- Сохранение параметров раскладки в истории и снимках для статистики. Смена текущей конфигурации не должна подменять параметры уже сохранённых слов.
- Преобразование статистики в потоке статистики, достигнутое в [задаче 24.7](24.7.md). Преобразование также требуется при выборе цели автосвича в потоке ввода.
- Независимость результата исправления от успешности чтения раскладки для статистики.

## Критерии завершения

- Обращения к KDE и чтение `kxkbrc` сосредоточены в `kde`; преобразование XKB реализовано отдельно.
- История, правила автосвича и статистика используют общее описание `Layout` и один интерфейс преобразования.
- Метод преобразования раскладки называется `Layout::to_text`; владение будущим кешем закреплено за объектом `Layout`.
- Проверка идентификатора по реестру реализована в `xkb` и вызывается из `kde` при разрешении цели; проверка наличия раскладки в конфигурации KDE остаётся в `kde`.
- Ошибки преобразования различимы, каждая ошибка логируется. Автосвич продолжает следующие правила после ошибки одной цели; статистика пропускает связанную запись целиком. Потеря ожидаемого текста не скрывается пропуском клавиши.
- Сохранены тесты преобразования, разрешения целей, переключения и наблюдения, включая порядок сообщений при завершении исправления. Тесты перенесены или обновлены согласно новым границам.
- Выполнены тесты приложения и линтинг; ограничения выполнения тестов, требующих D-Bus или живой сессии KDE, явно указаны в результате реализации.
