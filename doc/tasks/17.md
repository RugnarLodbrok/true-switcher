# Задача 17. Поиск qdbus с учётом имени команды в дистрибутиве

## Статус

- [x] Поиск команды в установщике и при запуске программы реализован.
- [x] Автоматические тесты и документация добавлены.
- [ ] Установка на Bazzite и ручной тест исправления слова.

## Проблема

После обновления Bazzite `make install` останавливается с ошибкой `qdbus is unavailable in the system service PATH.`

В системе установлены `/usr/bin/qdbus-qt6` и `/usr/lib64/qt6/bin/qdbus`; оба файла принадлежат пакету `qt6-qttools`. Однако установщик ищет только имя `qdbus` в `SYSTEM_PATH`, где каталога `/usr/lib64/qt6/bin` нет. Программа в `src/environment.rs` также запускает только `qdbus`.

## Решение

Использовать уже установленную утилиту из Qt6. Поддержать имена `qdbus-qt6`, `qdbus6` и `qdbus` в указанном порядке: сначала явно обозначенные варианты Qt6, затем общее имя.

Отдельно устанавливать другую версию утилиты, создавать системный симлинк или добавлять каталог Qt конкретного дистрибутива в `PATH` не требуется. На текущей Bazzite должен выбираться `/usr/bin/qdbus-qt6`.

## План реализации

1. В `installer/installer.py` заменить проверку единственного имени поиском по списку кандидатов через `shutil.which(..., path=SYSTEM_PATH)`. Проверять именно окружение будущего системного сервиса, а не пользовательский `PATH`. Выводить найденный путь; при отсутствии всех кандидатов перечислять проверенные имена и используемый `PATH` в сообщении об ошибке.
2. В `src/environment.rs` добавить выбор исполняемого файла при создании `KdePlasma`. Искать кандидатов в `PATH` процесса, сохранять выбранный абсолютный путь в структуре и использовать его при переключениях. Изменить создание `KdePlasma` в `src/main.rs`, чтобы отсутствие команды обнаруживалось при запуске, до обработки исправлений слова.
3. Сохранить одинаковые порядок кандидатов и правила выбора в установщике и программе. Для установленного сервиса оставить текущий `SYSTEM_PATH`; при прямом запуске программа использует свой `PATH`.
4. После выбора команды не пробовать другие имена при ошибке её запуска или ненулевом коде завершения: ошибка D-Bus не означает, что нужна другая утилита. В диагностике указывать выбранный путь и сохранять вывод ошибки команды. Аргументы вызова KDE оставить прежними.
5. В `README.md` уточнить требование: нужна утилита `qdbus` с одним из поддерживаемых имён, доступная в окружении запуска; для текущей Fedora/Bazzite она поставляется пакетом `qt6-qttools`.

## Тесты

- По отдельности проверить окружения, где доступно только одно из трёх имён, включая исходный сбой: есть `qdbus-qt6`, но нет `qdbus`.
- При наличии нескольких кандидатов проверить приоритет выбора.
- Проверить отсутствие кандидатов и пропуск файлов без права исполнения.
- Для установщика проверить, что команда только в пользовательском `PATH` не удовлетворяет проверке `SYSTEM_PATH`.
- Для программы использовать временные исполняемые файлы: проверить аргументы вызова, сообщение об ошибке и отсутствие повторного вызова через другое имя после ошибки выбранной команды. Тесты не должны переключать раскладку реальной сессии.

## Ручное тестирование

На Bazzite выполнить установку, убедиться, что выбран `/usr/bin/qdbus-qt6`. Запустить установленный сервис и проверить исправление слова по Pause. Установка и ручной тест пока не выполнялись.

- `cargo test --bin true-switcher`: 50 тестов прошли, 1 тест реальной сессии KDE штатно пропущен. Для тестов изолированной шины D-Bus потребовался запуск вне песочницы, запрещающей создание сокетов.
- `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s installer -p 'test_*.py' -v`: 5 тестов прошли. Дополнительные зависимости Python не требуются.
- Тесты Rust дополнительно проверяют сохранение имени симлинка при запуске: утилита, выбирающая поведение по имени вызова, должна получать выбранное имя команды.
