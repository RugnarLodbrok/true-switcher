# Задача 24.23. Компиляция XKB-карт на пути каждого символа

Вынесено из пункта 3 [задачи 24](24.md). Реализовано; решения по вопросам 1–3 приведены ниже.

Место: `src/layout.rs`, `Layout::to_text`; `src/xkb.rs`, `to_text`, `convert` и `compile_keymap`; `src/switch_rules.rs`, `AutoSwitchRules::target`.

**Состояние после [задачи 24.13](24.13.md):** разделение `layout`, `xkb` и `kde` реализовано. `Layout::to_text` делегирует преобразование модулю `xkb`; `Layout::to_text` и `Word::text` возвращают `Result` с `ConversionError`. Причины ошибок различимы, каждая возникшая ошибка логируется один раз. Предпосылки для кеширования выполнены; само кеширование в 24.13 не входило.

**Состояние до реализации:** `xkb::convert` при каждом вызове создавал контекст, компилировал карту и создавал `xkb::State`. `AutoSwitchRules::target` перебирал правила до первого совпадения и вызывал `rule.target.to_text(word.strokes())` для каждой цели, имя которой отличается от текущей раскладки. После очередного символа всё слово преобразовывалось заново; правила с одинаковой целью повторяли преобразование в пределах одного вызова `target`. При ошибке одной цели перебор продолжался.

Преобразование также вызывается из `Word::text` для последовательных участков слова с одинаковой сохранённой раскладкой и при подготовке статистики исправлений. После задачи 24.7 статистика преобразуется в отдельном потоке; автосвич — в потоке ввода. Снимки раскладок передаются через `Arc<Layout>`.

**Согласованные границы из 24.13:**

- Первоначальное решение о владении кешем объектом `Layout` пересмотрено в этой задаче: кеш принадлежит потоку и находится в `xkb` (см. «Согласованное хранение карт»). Потребители продолжают вызывать `Layout::to_text`.
- Карта должна соответствовать всем параметрам `name`, `variant`, `model`, `options`. Состояние кеша не участвует в сравнении раскладок.
- Сохранённые в истории и статистике параметры не подменяются текущей конфигурацией KDE.
- Сохраняются `ConversionError`, отказ от частичного текста, продолжение правил после ошибки цели и пропуск связанной записи статистики при ошибке преобразования. Поддержка Compose не добавляется.

**Результат:** скомпилированные карты кешируются, а результат преобразования для одинаковых параметров цели повторно используется в пределах одного вызова `AutoSwitchRules::target` с сохранением порядка правил и выбора первого совпадения. Новый символ требует нового преобразования слова, но не новой компиляции уже подготовленной карты. Для каждого преобразования создаётся собственное `xkb::State`.

**Ограничения реализации:** в используемой версии `xkbcommon` 0.9.0 типы `Context`, `Keymap` и `State` содержат сырые указатели и не реализуют `Send`/`Sync`. Простое добавление карты в `Layout`, в том числе через `Mutex`, несовместимо с передачей `Arc<Layout>` между потоками. Выбрано хранение через `thread_local!`; добавление `unsafe impl Send/Sync` не требуется. Поля параметров `Layout` закрыты и неизменяемы после создания.

Основные изменения затронули `src/layout.rs`, `src/xkb.rs`, `src/switch_rules.rs` и их тесты. Конструирование раскладок в `kde` и тестах потребителей обновлено. Задача ранее обозначалась направлением 24.1; теперь выделена в 24.23.

## Согласованное хранение карт

- Каждый поток создаёт и использует собственные XKB-карты. Объекты `Context`, `Keymap` и `State` между потоками не передаются; между потоками доступны параметры раскладки.
- В `xkb` используется `thread_local!` со словарём `HashMap`: ключ — значения всех четырёх параметров `name`, `variant`, `model`, `options`, значение — скомпилированная карта. Каждый поток получает собственный словарь; идентификаторы потоков в ключах не нужны.
- `Layout::to_text` остаётся точкой доступа для потребителей. Модуль `xkb` ищет карту по параметрам переданного `Layout` в словаре текущего потока. Сам `Layout` XKB-объектов не содержит и владельцем кеша не является; это согласованный пересмотр решения 24.13.
- Карта создаётся лениво, при первом преобразовании с соответствующими параметрами в данном потоке. Успешно скомпилированная карта используется повторно без перекомпиляции. Для одного набора параметров в двух потоках возможны две первоначальные компиляции.
- Карты хранятся до завершения соответствующего потока и освобождаются при уничтожении его словаря. Изменение настроек или уничтожение `Layout` не удаляет карты: записи для прежних параметров остаются доступными для повторного использования до завершения потока.

## Неизменяемые параметры `Layout`

- Параметры `name`, `variant`, `model`, `options` задаются через конструктор. Поля закрыты; публичный доступ к параметрам предоставляется только для чтения.
- При изменении конфигурации KDE создаётся новый `Layout`. Существующие снимки в истории и статистике сохраняют исходные параметры.
- Ключ кеша включает значения всех четырёх параметров. Неизменяемость `Layout` обеспечивает целостность снимков конфигурации.

## Ошибки компиляции и логирование

- В кеше потока сохраняются только успешно скомпилированные карты. Ошибка компиляции не кешируется; при следующем обращении, требующем эту карту, компиляция повторяется.
- Отдельного цикла повторных попыток нет. Попытки связаны с запросами преобразования при вводе и обработке статистики.
- Каждое неуспешное преобразование логируется один раз, без дублирования между слоями. При следующем обращении новая ошибка логируется снова, даже если её причина совпадает с предыдущей; ограничение частоты логирования не вводится.
- В пределах одного вызова `AutoSwitchRules::target` для одинаковых четырёх параметров цели повторно используется весь результат преобразования, включая ошибку. Повторное использование ошибки не вызывает новой компиляции и не создаёт дополнительной записи в логе. При следующем вызове `target` попытка повторяется.
- Принято, что постоянная ошибка цели может приводить к записи в логе на каждом введённом символе, пока эта цель проверяется правилами.
