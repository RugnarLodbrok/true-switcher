# Границы слов по strong punctuation

## Context

`History` сейчас начинает новое слово по счётчику завершающих пробелов. `Word` хранит физические нажатия для коррекции и путь префикса для каждого словаря. `Input` использует событие первого пробела для точного поиска, обновления ожидающего свича и отметки неоднозначности.

## Goals / Non-Goals

Одна граница слова для истории, ручной коррекции и `switch_rules`. Для словарного поиска и `teach` нужен текст без краевых `strong pnt`. При построении `trie2` сохранённые ключи приводятся к новым границам.

## Decisions

- Определять `strong pnt` по `Stroke` и актуальному списку активных раскладок KDE. Использовать существующее преобразование XKB и полное совпадение с `punctuation` в каждой раскладке. Если список пуст, преобразование недоступно или результат хотя бы в одной раскладке не подходит, нажатие не образует новую границу. Пустой `punctuation` отключает классификацию. Обновлять классификацию при изменении активных раскладок и настроек.
- Хранить полную последовательность нажатий и выделять в ней диапазон для словарного поиска. Начальная серия `strong pnt` ждёт первого `Stroke` вне `strong pnt`. Этот `Stroke` начинает поисковый диапазон, даже если в текущей раскладке он даёт пунктуацию. Первый `strong pnt` после него закрывает диапазон, остальная серия присоединяется для коррекции. Поэтому `~/home` в US делится на `~/` и `home`, если `~` соответствует `Ё` в RU, а `/` соответствует точке. Backspace убирает реальные нажатия, а удаление последнего разделителя возвращает слово к префиксному поиску. Серия только из `strong pnt` ждёт поискового диапазона.
- Использовать общее событие первого завершения слова для пробела и `strong pnt`. Передавать обоим trie диапазон для поиска и признак точного совпадения, добавляя один `WORD_END` к ключу. Остаточная пунктуация внутри поискового диапазона обрабатывается действующими правилами словарного скоринга. На каждом завершающем `strong pnt` и каждом завершающем пробеле проверять `switch_rules` на полном слове со всеми введёнными знаками и пробелами. После первой границы дополнительные знаки и пробелы расширяют диапазон коррекции без повторной словарной оценки.
- Проверять `switch_rules` при вводе начальной пунктуации, даже если для словарного поиска ещё нет текста. Например, на втором нажатии `Ё.` в RU правило `^~/` уже получает полный префикс в целевой US.
- Разрешить обход цепочки через границу из `strong pnt` без пробела по константе в коде со значением `true`. Использовать одну и ту же проверку границы при суммировании дельта-скоров и выборе диапазона перепечатывания. Ручная коррекция снимает отметку неоднозначности с исправленного слова.
- Для `teach` переводить в текст целевой раскладки тот же диапазон нажатий, который используется для словарного поиска без краевых `strong pnt`. Это сохраняет символы `semi-strong pnt`, набранные обычным нажатием.
- В `learned-rules.toml` хранятся строки. При построении `trie2` проверять все `Stroke`, которыми можно набрать краевой символ в раскладке записи. Удалять символ, если существует хотя бы один такой `Stroke` и все они считаются `strong pnt`. Суммировать счётчики совпавших ключей в пределах раскладки. Например, `/new = 3` и `new = 2` дают `new` со счётчиком `5`, если `/` в этой раскладке вводится только через `strong pnt`. Обрезку применять только к ключу индекса, чтобы смена набора раскладок обходилась без миграции файла.

## Risks / Trade-offs

- Статус `strong pnt` зависит от всех активных раскладок и вариантов XKB. Например, один и тот же текстовый знак может завершать слово на одном физическом нажатии и оставаться внутри слова на другом.
- Общие дефис и подчёркивание делят составные слова и идентификаторы. Полные совпадения `switch_rules`, рассчитанные на прежний токен с такими разделителями, будут получать отдельные слова.

## Пример разбиения и скоринга

Стандартная пара US/RU, ISO-клавиатура. Для примера все символы вводятся в US, а вычисленные запросы на коррекцию не выполняются. В квадратных скобках показаны полные диапазоны коррекции. Пробел внутри ключа в кавычках — один `WORD_END`.

Два символа `<` в `next<part<tail` набраны разными `Stroke`. Первый, через Shift + клавишу запятой, даёт `Б` в RU и остаётся внутри слова как `weak pnt`. Второй, через дополнительную ISO-клавишу, даёт `/` в RU и завершает слово как `strong pnt`. Поэтому сам символ `<` в US — `semi-strong pnt`.

```text
Input:   ~/home///a;b__config  //new?next<part<tail
Words:  [~/][home///][a;b__][config  ][//new?][next<part<][tail]

Correction span   Main US lookup key   Match
---------------   ------------------   ------
[~/]              "~ "                 exact
[home///]         "home "              exact
[a;b__]           "a;b "               exact
[config  ]        "config "            exact
[//new?]          "new "               exact
[next<part<]      "next<part "         exact
[tail]            "tail"               prefix
```

```text
~                  Начинает слово. В RU этот Stroke даёт Ё.
`- /               Закрывает [~/]. Regex получает "~/", trie ищут по "~ ".

home               Поиск по префиксу "home".
`- /               Закрывает слово и запускает точный поиск "home ".
   `- //           Regex получает "home//", затем "home///". Словарный поиск не повторяется.

a;b                ";" остаётся внутри: в RU этот Stroke даёт ж.
`- _               Закрывает слово. Точный ключ — "a;b ".
   `- _            Присоединяется к [a;b__].

config             Поиск по префиксу "config".
`- Space           Закрывает слово. Точный ключ — "config ".
   `- Space        Regex получает "config  ". Оба пробела входят в диапазон коррекции.

//                 Начальная серия после пробелов ждёт следующего текста.
`- new             Поиск по префиксу "new". Диапазон коррекции — "//new".
   `- ?            Закрывает [//new?]: в RU этот Stroke даёт ",".
                   Точный ключ — "new ". Regex получает "//new?".

next
`- <   Shift + ,   В RU получается Б. Weak pnt: остаётся внутри.
   `- part
      `- <   ISO   В RU получается /. Strong pnt: закрывает [next<part<].
                   Точный ключ — "next<part ".

tail               Слово открыто. Поиск по префиксу "tail".
```

- Если стереть `tail`, а затем второй `<`, слово `next<part` снова открывается. Его пометка неоднозначности сбрасывается, и дальнейший ввод продолжает префикс.
- Ручной свич сразу после `home///` перепечатывает весь диапазон с тремя знаками. Если такое слово исправлено через `teach` в US, сохранённый ключ — `home`.
- Если `home///` помечено как неоднозначное и выполняются условия цепочки, скор следующего слова `a;b` может включить `home///` в один словарный свич. Для паттерн-свича по `^~/` уже достаточно `Ё.` в RU: правило в целевой US видит `~/` при вводе точки.
