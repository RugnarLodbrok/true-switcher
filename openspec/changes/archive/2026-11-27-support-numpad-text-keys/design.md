# Design

## Context

Сейчас `is_text_key` определяет, какие нажатия сохраняет `History` и принимает `replay_strokes`. В `src/punctuation.rs` функция `text_strokes` перебирает текстовые нажатия только до `KEY_102ND`. `KeyboardOutput::new` регистрирует keycode виртуальной клавиатуры, а `is_repair_key` определяет, какие скрытые нажатия восстанавливает `Interceptor` при откате входа в захват.

## Goals / Non-Goals

**Goals**

- Определить единый набор физических текстовых клавиш для истории, strong punctuation, синтетического ввода и восстановления при откате.

**Non-Goals**

- Отслеживание Num Lock для цифр и клавиши `Decimal/Delete`, изменение последовательности захвата и правил словарной оценки.
- Обработка `NoTextForKey` при синтетическом вводе отложена до отдельного change `support-no-text-strokes`.

## Decisions

- Определить набор в `src/key_codes.rs`, включая текущие текстовые клавиши и текстовые клавиши нумпада. Предоставить `is_text_key(key: KeyCode) -> bool` для проверки принадлежности и `text_keys() -> impl Iterator<Item = KeyCode>` для перебора того же набора.
- `History` и `replay_strokes` проверяют нажатия через `is_text_key`. `is_repair_key` использует эту же проверку вместе с правилами восстановления остальных клавиш.
- `KeyboardOutput::new` регистрирует клавиши из `text_keys()`. `text_strokes` использует тот же итератор и создаёт для каждого keycode два `Stroke` с обоими состояниями Shift. Действующая карта XKB определяет символ, а правило strong punctuation учитывает все активные раскладки.

## Risks / Trade-offs

- Набор символов зависит от карты XKB. Например, `KEY_KPJPCOMMA` имеет текстовое назначение на японских клавиатурах Apple с соответствующей картой. До отдельного исправления при `NoTextForKey` в исходной раскладке ручная коррекция может отправить лишний Backspace.
