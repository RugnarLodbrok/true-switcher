# Словарная оценка токенов с конечной пунктуацией

## Context

`History` закрывает слово на первом пробеле или завершающем `strong pnt`. После `common-trie-api` `DictionaryAutoSwitch::layout_score` один раз на раскладку переводит `Word::search_strokes()` в текст и передаёт исходный ключ и остаток после начальной обрезки в `LayoutIndexes::score`. Каждый вызов проходит оба trie от корня и возвращает пару из словарного скора и счётчика сохранённых примеров. Для точного поиска вызывающий код добавляет `WORD_END` (один пробел). `Word` хранит нажатия, а после Backspace следующие ключи строятся из обновлённой истории.

## Goals / Non-Goals

Расширить подготовку ключей перед `LayoutIndexes::score`. `LearnedRules` обслуживает `teach` и нормализацию краевых `strong pnt` при индексации. Проверять `punctuation protection` по полному токену текущей раскладки. При коррекции перепечатывать весь диапазон, выбранный по действующим правилам.

## Decisions

- Проверять AST `punctuation` при загрузке конфига через `regex-syntax`. Разрешать одиночный Unicode-литерал, Unicode-класс, их группировку и альтернативы. Допускать пустую строку для отключения. Квантификаторы, последовательности символов и позиции вроде `^` отклонять с ошибкой конфигурации.
- Компилировать полный шаблон одиночного символа для классификации `Stroke`. Для `punctuation protection` и краевой обрезки компилировать шаблоны серии `(?:pattern)+` с нужными якорями `\A` и `\z`.

### Три варианта скора раскладки

Один раз перевести `Word::search_strokes()` в текст каждой раскладки. В каждой раскладке независимо оценить до трёх вариантов.

1. **Исходный текст.** Искать весь текст как префикс, пока слово открыто. На первой границе слова (пробеле или завершающем `strong pnt`) искать точный ключ.
2. **Текст после краевой обрезки.** Найти начальную и конечную серии `punctuation` в исходном тексте и взять один общий остаток. Если снята конечная пунктуация, сразу искать точный ключ. Если снята только начальная, искать префикс до первой границы слова и точный ключ на границе. Если текст не изменился или остаток пуст, этот вариант пропустить.
3. **Части по внутренней пунктуации.** Разделить переведённый текст по символам `punctuation` и пропустить пустые части. Если осталось хотя бы две части, все части до последней искать точно. Последнюю искать точно при снятой конечной пунктуации или на первой границе слова, иначе искать её как префикс. Скор варианта равен минимуму итоговых скоров частей.

Для точного поиска добавить один `WORD_END` к ключу перед вызовом `LayoutIndexes::score(key)`. Метод возвращает итоговый `f64`, складывая словарный скор и счётчик `teach` того же ключа. Если ключ найден только в `trie2`, его скор равен `−18 + счётчик`. Если ключ отсутствует в обоих trie, его скор равен `−∞`.

Скор раскладки равен максимуму из доступных вариантов. Дельта-скор равен скору альтернативной раскладки минус скор текущей. Если обе раскладки получили `−∞`, дельта-скор равен `0`.

### Диагностика

`score_separated(key)` возвращает базовый скор и счётчик того же ключа для `score` CLI и debug-лога. `score(key)` использует те же составляющие и правила подстановки `−18`. Диагностика использует тот же выбор по итоговым скорам и показывает составляющие выбранного ключа. Для разбитого варианта это ключ части с минимальным итоговым скором.

## Risks / Trade-offs

Конечная `weak pnt` может запустить словарный автосвич, пока слово открыто. При следующем скоринге край определяется заново. Например, после допечатывания `git;hub` точка с запятой становится внутренней. Пометки `ambiguous word` и отложенной коррекции по-прежнему создаются по действующим правилам на первой фактической границе слова.
