# Spec Delta

## MODIFIED Requirements

### Requirement: Выбор по префиксу

При включённом `auto_switch` True Switcher SHALL сравнивать дельта-скор с порогом целевого словаря. True Switcher SHALL использовать максимальный итоговый скор в каждой раскладке по правилу «Словарная оценка начальной пунктуации». Словарный скор ключа равен `log2(P)`, где `P` — нормированная частота в конечном узле пути. На первой границе слова (пробел или завершающий `strong pnt`) к каждому ключу поиска добавляется один завершающий пробел.

True Switcher SHALL блокировать словарный кандидат, если полный токен в текущей раскладке без завершающих пробелов состоит из одного или нескольких символов `punctuation`, при любом значении `pattern_switch`. На первой границе слова SHALL применяться правило «Отложенная словарная коррекция при блокировке пунктуации».

#### Scenario: Ключ в словарном trie

- **WHEN** пользователь вводит `git`, а затем первый завершающий пробел
- **THEN** до пробела используется узел `git` с частотой всех слов с этим префиксом, а после пробела — узел `git ` с частотой точного слова `git`

#### Scenario: Выбор по префиксу

- **WHEN** дельта-скор равен порогу
- **THEN** словарный запрос не создаётся

#### Scenario: Одиночный знак и повторения сохраняются

- **WHEN** действует паттерн по умолчанию, пользователь в US-раскладке вводит один или три бэктика, `""` либо `''`, а словарная оценка в пользу RU прошла бы порог
- **THEN** словарный запрос не создаётся при наборе и на первом завершающем пробеле

#### Scenario: Тильда и угловые скобки защищены

- **WHEN** действует паттерн по умолчанию, токен `~`, `<` или `>` в текущей раскладке совпадает с ним полностью и словарная оценка в другой раскладке проходит порог
- **THEN** словарный запрос не создаётся

#### Scenario: Смешанная пунктуация защищена

- **WHEN** действует паттерн по умолчанию и токен `../`, `!?` или сочетание бэктика с `;` в US проходит словарный порог
- **THEN** словарный запрос не создаётся при наборе и на первом завершающем пробеле, в том числе при выключенном `pattern_switch`

#### Scenario: Разные знаки оцениваются по словарю

- **WHEN** задано `punctuation = '[./\\]'`, пользователь в US вводит бэктик и `;`, словарная оценка для `ёж` проходит порог и применимых `switch_rules` нет
- **THEN** создаётся словарный запрос в RU-раскладку

#### Scenario: Смена состояния Shift

- **WHEN** действует паттерн по умолчанию, пользователь вводит `'"` одной клавишей, сначала без Shift, затем с Shift, и токен проходит словарный порог
- **THEN** словарный запрос не создаётся

#### Scenario: Паттерн проверяется на всём токене

- **WHEN** действует паттерн по умолчанию, а токен `v1.2` проходит словарный порог и применимых `switch_rules` нет
- **THEN** True Switcher создаёт словарный запрос

#### Scenario: Пунктуация в альтернативной раскладке оценивается по словарю

- **WHEN** пользователь в RU-раскладке набирает `жжение`, а префиксу `жж` соответствует `;;` в US-раскладке
- **THEN** вариант `;;` получает обычную словарную частоту без бонуса за пунктуацию

#### Scenario: Повторяющаяся пунктуация при обучении

- **WHEN** поправка поднимает словарный дельта-скор выше порога для токена из повторяющихся символов `punctuation`
- **THEN** словарный автосвич пропускается

### Requirement: Конфигурация начальной пунктуации

True Switcher SHALL принимать необязательный regex `punctuation` в корне `config.toml`. Regex SHALL задавать набор одиночных Unicode-символов с помощью литералов, классов, группировки и альтернатив. Для блокировки и краевой обрезки True Switcher SHALL распознавать серии таких символов. Значение по умолчанию в коде и `installer/config.example.toml` SHALL быть `` '[`~<>\p{P}]' `` в TOML. Пустая строка SHALL отключать блокировку, границы по `strong pnt` и оценку пунктуации. Некорректный шаблон SHALL вызывать ошибку с указанием `punctuation`.

#### Scenario: Параметр отсутствует

- **WHEN** в конфиге отсутствует `punctuation`
- **THEN** `~<.git` оценивается также как `git`

#### Scenario: Настройка используется при оценке

- **WHEN** `punctuation = '[$]'`, `$` введён через `weak pnt` и пользователь набирает токен
- **THEN** `$git` дополнительно оценивается как префикс `git`, `git$` — как точное слово `git`, а `.git` и `git.` оцениваются целиком

#### Scenario: Пустое значение

- **WHEN** `punctuation = ''`
- **THEN** в каждой раскладке для словаря и сохранённых примеров используется только полный токен
- **AND** допустимый по остальным правилам словарный запрос для `../` создаётся

#### Scenario: Невалидный regex

- **WHEN** задано `punctuation = '['`
- **THEN** загрузка конфигурации завершается ошибкой с указанием `punctuation`

#### Scenario: Regex задаёт набор одиночных Unicode-символов

- **WHEN** `punctuation = ';|ж'`
- **THEN** `;` и `ж` распознаются по одному, а для защиты целого токена `;ж;` распознаётся как серия пунктуации

#### Scenario: Квантификаторы и последовательности в конфиге

- **WHEN** задано `punctuation = '[!?]+'`, `punctuation = ';;|жж'` или `punctuation = ';?'`
- **THEN** загрузка конфигурации завершается ошибкой с указанием `punctuation`

### Requirement: Словарная оценка начальной пунктуации

True Switcher SHALL брать за исходный ключ текст диапазона для словарного поиска без краевых `strong pnt`. В каждой раскладке True Switcher SHALL сравнивать скор исходного ключа со скором одного непустого остатка после обрезки совпадений `punctuation` по краям этого ключа. Пока слово открыто, исходный ключ SHALL оцениваться как префикс. Остаток SHALL оцениваться как точное слово при удалении конечной пунктуации и как префикс в остальных случаях. На первой границе слова оба варианта SHALL оцениваться как точные слова. При автосвиче True Switcher SHALL перепечатывать весь диапазон коррекции с его пунктуацией.

True Switcher SHALL определять внутренние разделители по символам `punctuation` в переведённом тексте поискового диапазона каждой раскладки. В каждой раскладке, где разделители делят исходный ключ на несколько непустых частей, True Switcher SHALL считать минимум итоговых скоров её частей третьим вариантом скора. Все части до последней SHALL оцениваться как точные слова. Последняя SHALL оцениваться как точное слово при обрезке конечной пунктуации или на первой границе слова, иначе как префикс. При расчёте дельта-скора True Switcher SHALL использовать максимум применимых вариантов в каждой раскладке.

#### Scenario: Начальная пунктуация в альтернативной раскладке

- **WHEN** пользователь набирает `юпше` в RU и словарь US даёт `git` больший скор, чем `.git`
- **THEN** для словаря US используется скор `git`, а для словаря RU — скор `юпше`
- **AND** если словарный автосвич срабатывает, результатом является `.git`

#### Scenario: Начальная пунктуация в текущей раскладке

- **WHEN** пользователь набирает `.git` в US и словарь US даёт `git` больший скор, чем `.git`
- **THEN** скор `git` используется как скор текущей раскладки и вычитается при вычислении дельта-скора

#### Scenario: Полный токен даёт больший скор

- **WHEN** `.git` даёт больший скор, чем `git`
- **THEN** используется скор `.git`

#### Scenario: Первый пробел после токена с начальной пунктуацией

- **WHEN** пользователь вводит первый пробел после `.git`, а `git` присутствует в словаре только как префикс, например у слова `github`
- **THEN** совпадение с префиксом `git` перестаёт влиять на словарный скор, а `.git` оценивается по частоте точного слова

#### Scenario: Пунктуация внутри токена

- **WHEN** при настройке по умолчанию нажатия `weak pnt` дают в US исходный ключ `a.git` или `;a.git`
- **THEN** краевая обрезка для `a.git` отсутствует, а для `;a.git` даёт `a.git`

#### Scenario: Совпадение без остатка

- **WHEN** обрезка удаляет весь токен `;;`
- **THEN** словарь оценивает только `;;`

#### Scenario: Пунктуация только в конце

- **WHEN** при настройке по умолчанию пользователь набирает `git;` в US, а то же нажатие `;` в RU даёт `ж`
- **THEN** исходный ключ US оценивается по префиксу `git;`, остаток US — по точному ключу `git `, а исходный ключ RU — по префиксу `пшеж`
- **AND** если в словаре есть `github` и нет точного `git`, частота `github` не участвует в скоре остатка

#### Scenario: Пунктуация с двух краёв

- **WHEN** пользователь набирает `;git;` в US при настройке по умолчанию и оба `;` введены как `weak pnt`
- **THEN** в US оцениваются префикс `;git;` и точный ключ `git `, и применяется больший скор

#### Scenario: Первая граница после конечной weak punctuation

- **WHEN** после `git;` в US с конечной `weak pnt` пользователь вводит пробел или завершающий `strong pnt`
- **THEN** точные ключи US — `git; ` и `git ` при настройке по умолчанию
- **AND** дальнейшие разделители обрабатываются по правилу «Автосвич на strong punctuation» без повторного словарного поиска

#### Scenario: Пунктуация снова становится внутренней

- **WHEN** пользователь допечатывает `hub` к `git;` с конечной `weak pnt` и токен становится `git;hub`
- **THEN** при настройке по умолчанию исходный вариант оценивается по префиксу `git;hub`, а `;` со следующего скоринга обрабатывается как внутренний знак

#### Scenario: Разбиение только в текущей раскладке

- **WHEN** токен в текущей раскладке — `foo.bar`, а в альтернативной внутреннего совпадения `punctuation` нет
- **THEN** при наборе для разбитого варианта ищутся ключи `foo ` и `bar`
- **AND** если далее обрезается конечный знак или слово достигает первой границы, при сохранении условия разбиения для последней части используется `bar `

#### Scenario: Разбиение только в альтернативной раскладке

- **WHEN** при настройке по умолчанию пользователь набирает `ащщюифк` в RU, тем же нажатиям в US соответствует `foo.bar`, а в словаре US есть `foo` и `bar`
- **THEN** при наборе US получает дополнительный скор как минимум скоров `foo ` и `bar`, а на первой границе слова использует минимум скоров `foo ` и `bar `
- **AND** если дельта-скор проходит порог US и остальные условия словарного автосвича выполнены, True Switcher запрашивает свич в US

#### Scenario: Разные границы разбиения в обеих раскладках

- **WHEN** при настройке по умолчанию пользователь набирает `foo;bar$baz` в US и тем же нажатиям в стандартной RU-раскладке соответствует `ащщжифк;ифя`
- **THEN** при наборе разбитый вариант US использует минимум скоров `foo ` и `bar$baz`, а разбитый вариант RU — минимум скоров `ащщжифк ` и `ифя`
- **AND** для расчёта дельта-скора в каждой раскладке выбирается максимум из её применимых вариантов

#### Scenario: Разбиение многосимвольного результата нажатия

- **WHEN** одно нажатие даёт поисковый текст `a.b` в оцениваемой раскладке и `.` совпадает с `punctuation`
- **THEN** при скоринге открытого слова используется разбиение с ключами `a ` и `b`

#### Scenario: Слабейшая часть определяет скор разбитого варианта

- **WHEN** полный, обрезанный и два отдельных ключа в текущей раскладке дают скоры `−20`, `−18`, `−4` и `−14`, а словарный скор альтернативной раскладки равен `−10`
- **THEN** скор разбитого варианта и выбранный скор текущей раскладки равны `−14`, а дельта-скор равен `+4`

#### Scenario: Часть отсутствует в словаре

- **WHEN** одна из частей разбитого варианта отсутствует в обоих trie оцениваемой раскладки
- **THEN** скор разбитого варианта равен `−∞`, а для дельта-скора применяются остальные варианты поиска

### Requirement: Поправка к словарному дельта-скору по сохранённым примерам

True Switcher SHALL вычислять итоговый скор для каждого ключа как сумму базового скора и счётчика сохранённых примеров этого же ключа. Для префикса счётчик равен сумме по сохранённым словам с таким префиксом. Для точного ключа он равен числу сохранений точного слова. Отсутствие совпадения в `trie2` даёт счётчик `0`. В каждой раскладке True Switcher SHALL выбирать максимум итоговых скоров по вариантам и брать их разность в порядке альтернативная минус текущая.

#### Scenario: Предпочтение получившейся раскладки

- **WHEN** сохранённый пример в альтернативной раскладке совпадает с префиксным ключом, скор которого определяет итог этой раскладки
- **THEN** его счётчик повышает дельта-скор переключения в эту раскладку

#### Scenario: Сохранение текущей раскладки

- **WHEN** сохранённый пример в текущей раскладке совпадает с префиксным ключом, скор которого определяет итог этой раскладки
- **THEN** его счётчик понижает дельта-скор переключения из этой раскладки

#### Scenario: Переход от префикса к точному слову

- **WHEN** `кот` сохранён дважды, `котик` трижды в той же раскладке и пользователь вводит `кот` с пробелом
- **THEN** счётчик ключа равен пяти на префиксе `кот` и двум на первом пробеле

### Requirement: Базовый скор при отсутствии словарного совпадения

True Switcher SHALL брать для ключа его словарный скор как базовый. Если ключ найден только в `trie2` с положительным счётчиком, базовый скор SHALL быть `−18`. Правило действует отдельно для каждого префиксного и точного ключа. Если ключ отсутствует в обоих trie, его итоговый скор SHALL быть `−∞`. Если конечный итоговый скор есть только в альтернативной раскладке, дельта-скор SHALL быть `+∞`, если только в текущей — `−∞`. Если итоговый скор обеих раскладок равен `−∞`, дельта-скор SHALL быть `0`.

#### Scenario: Сохранённый пример вне основного словаря

- **WHEN** ключ, определяющий итог одной раскладки, найден только среди сохранённых примеров, а для другой раскладки есть словарное совпадение
- **THEN** для первого ключа используется базовый скор `−18`, и дельта-скор конечен

#### Scenario: Масштаб словарных частот

- **WHEN** все частоты словаря умножены на один и тот же положительный множитель и ключ по-прежнему найден только среди сохранённых примеров
- **THEN** для этого ключа используется тот же базовый скор `−18`

#### Scenario: Базовый скор есть только в одной раскладке

- **WHEN** положительная частота или положительный счётчик есть только в одной раскладке
- **THEN** дельта-скор равен `+∞` для совпадения в альтернативной раскладке или `−∞` для совпадения в текущей

#### Scenario: Совпадений нет в обеих раскладках

- **WHEN** все ключи поиска в обеих раскладках отсутствуют в обоих trie
- **THEN** дельта-скор равен `0`, словарный запрос не создаётся

#### Scenario: Словарный ключ и ключ только из сохранённых примеров

- **WHEN** у исходного ключа словарный скор `−12` и счётчик `0`, а обрезанный ключ найден только в `trie2` со счётчиком `8`
- **THEN** итоговый скор обрезанного ключа равен `−18 + 8 = −10` и выбирается для раскладки
- **AND** если счётчик обрезанного ключа равен `3`, выбирается итоговый скор исходного ключа `−12`

## ADDED Requirements

### Requirement: Поиск сохранённых примеров по вариантам токена

При сохранении через `teach` и поиске сохранённых примеров True Switcher SHALL использовать диапазон для словарного поиска без краевых `strong pnt`. В `trie2` True Switcher SHALL искать по тем же ключам, что и в `trie1`, включая исходный ключ, остаток после краевой обрезки и ключи частей. Счётчик каждого ключа SHALL участвовать в расчёте итогового скора этого ключа.

#### Scenario: Индексация сохранённых ключей

- **WHEN** True Switcher строит `trie2` из `learned-rules.toml`
- **THEN** с краёв ключа удаляются знаки, для которых в раскладке записи существует хотя бы один `Stroke` и все способы ввода этого знака классифицируются как `strong pnt` для активных раскладок
- **AND** `semi-strong pnt` и внутренние знаки сохраняются, счётчики совпавших ключей одной раскладки суммируются, а пустые после обрезки ключи пропускаются
- **AND** исходные записи сохраняются в `learned-rules.toml`

#### Scenario: Пример без начальной пунктуации

- **WHEN** в US сохранён только пример `new`, а пользователь набирает `/new` с начальным `/` через `strong pnt`
- **THEN** пример `new` участвует в префиксном поиске при вводе `new` и в точном поиске на первом завершающем пробеле

#### Scenario: Пример с начальной пунктуацией

- **WHEN** в US сохранены `/new` со счётчиком `3` и `new` со счётчиком `2`, а все способы набрать `/` в US классифицируются как `strong pnt`
- **THEN** в `trie2` для US индексируется ключ `new` со счётчиком `5`, который используется при точном поиске для `/new`

#### Scenario: Semi-strong и внутренняя пунктуация

- **WHEN** в US сохранён ключ `<home/config/`, `<` — `semi-strong pnt`, а все способы набрать `/` в US классифицируются как `strong pnt`
- **THEN** в `trie2` индексируется `<home/config`

#### Scenario: Классификация знака изменилась

- **WHEN** после изменения набора активных раскладок краевой знак сохранённого ключа меняется с однозначного `strong pnt` на `semi-strong pnt`
- **THEN** при следующем построении `trie2` знак остаётся в индексируемом ключе, а исходная запись в файле доступна для повторной индексации

#### Scenario: Обрезанный ключ даёт больший счётчик

- **WHEN** в US сохранены `;git` один раз, `git` дважды и `github` трижды, а пользователь набирает `;git` с начальной `weak pnt`, которую обрезает `punctuation`
- **THEN** счётчик обрезанного ключа равен пяти при наборе префикса `;git` и двум на первой границе слова

#### Scenario: Словарный скор и счётчик относятся к одному ключу

- **WHEN** на первой границе после `;git` в US исходный ключ даёт словарный скор `−8` и счётчик `0`, а обрезанный ключ даёт словарный скор `−12` и счётчик `5`
- **THEN** выбирается итоговый скор `−7` обрезанного ключа

#### Scenario: Точный счётчик после конечной weak punctuation

- **WHEN** `git` сохранён дважды, `github` трижды и пользователь набирает `git;` с конечной `weak pnt` в US при настройке по умолчанию
- **THEN** счётчик обрезанного ключа равен двум уже при вводе `;` и на первой границе слова

#### Scenario: Teach сохраняет weak punctuation

- **WHEN** `teach` сохраняет `git;` с конечной `weak pnt` в US, `;` относится к `weak pnt` для всех способов его ввода в US и других сохранённых примеров нет
- **THEN** сохраняется ключ `git;`, а точный поиск слова `git` на первой границе даёт счётчик `0`

#### Scenario: Поиск частей использует одинаковые ключи в обоих trie

- **WHEN** пользователь набирает `foo.bar` в US, точка введена как `weak pnt` и образует внутреннюю границу в US
- **THEN** `trie1` и `trie2` ищут первую часть по ключу `foo `, а последнюю при наборе по ключу `bar` и на первой границе слова по ключу `bar `

#### Scenario: Минимум итоговых скоров частей

- **WHEN** итоговый скор исходного ключа равен `−7`, обрезанного ключа нет, а две части дают `−9 + 5` и `−7 + 2`
- **THEN** итоговый скор разбитого варианта равен `−5` и выбирается для раскладки
- **AND** если одна часть отсутствует в обоих trie, итоговый скор разбитого варианта равен `−∞` и выбирается исходный ключ со скором `−7`
