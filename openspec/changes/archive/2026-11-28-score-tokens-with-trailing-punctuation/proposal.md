# Словарная оценка токенов с конечной пунктуацией

## Why

Первый `strong pnt` уже закрывает слово и запускает точный поиск без этого знака. `Weak pnt` остаётся в слове. Например, в паре US/RU нажатие `;` в US даёт `ж` в RU, поэтому после ввода `git;` словарь US ищет `git;` и может потерять совпадение с `git`.

## What Changes

- **BREAKING** — `punctuation` задаёт набор одиночных Unicode-символов. Значение по умолчанию — `` '[`~<>\p{P}]' ``. Для поиска серии знаков True Switcher сам добавляет `+` к группе. Сохранённые шаблоны с квантификаторами нужно заменить вручную.
- Расширить подготовку ключей для общего `LayoutIndexes::score`. Снимать пунктуацию с обоих краёв одним вариантом и искать его точно, если с конца был удалён знак, даже у открытого слова.
- Складывать словарный скор и счётчик сохранённых примеров для одного ключа. Подставлять `−18`, если этот ключ найден только среди сохранённых примеров.
- Разбивать переведённый текст по внутренней пунктуации. Для разбитого варианта брать минимум итоговых скоров частей. Из применимых вариантов выбирать максимальный итоговый скор.
- Сохранять разбивку итогового скора на составляющие для `score` CLI и debug-лога.

## Capabilities

### Modified Capabilities

- `auto-switch` — учёт краевой и внутренней пунктуации при словарной оценке и поиске сохранённых примеров.

## Impact

Изменение касается подготовки ключей перед `LayoutIndexes::score` и расчёта дельта-скора, общего для автосвича и `score` CLI.
