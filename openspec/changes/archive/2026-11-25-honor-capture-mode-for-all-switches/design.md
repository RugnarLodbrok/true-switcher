# Выбор `CorrectionInterceptor`

## Context

`enter_interceptor` сейчас выбирает реализацию по `IS_CAPTURE_ENABLED` и длине диапазона. Стирание, replay и обновление `History` уже получают весь диапазон через `SwitchRequest` при любом `CorrectionInterceptor`.

## Goals / Non-Goals

Убрать зависимость выбора `CorrectionInterceptor` от длины диапазона. Состав диапазона по-прежнему определяется при формировании `SwitchRequest`.

## Decisions

- При `false` обработать доступные события, проверить актуальность запроса и войти в `UncapturedInterceptor`. Его существующий протокол отправляет синтетические `key-up` через исходные устройства и продолжает обработку физического ввода.
- При `true` войти в `Interceptor`, который применяет существующий протокол ожидания отпускания клавиш и `grab`.
- Тесты, предназначенные для протокола `grab`, должны явно выбирать этот режим. Регрессионный тест должен пройти через штатный выбор режима с многословным запросом и удерживаемым пробелом.

## Risks / Trade-offs

При `false` физический ввод может поступить во время более долгого стирания и replay нескольких слов. Действуют существующие правила обработки ввода и отмены `UncapturedInterceptor`.
