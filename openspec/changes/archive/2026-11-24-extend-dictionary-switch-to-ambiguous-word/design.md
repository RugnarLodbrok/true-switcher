# Дизайн словарного автосвича с учётом предыдущих слов

## Context

`DictionaryComparison` уже содержит скоры обеих раскладок и дельта-скор. `History` хранит физические клавиши, Shift, исходную раскладку и число пробелов по каждому слову. `SwitchRequest` передаёт предыдущее слово для статистики. Стирание, replay и обновление раскладки в истории сейчас привязаны к последнему слову.

## Goals / Non-Goals

Переиспользовать словарную оценку, протокол коррекции и существующую схему SQLite. Использовать один диапазон для коррекции, обновления истории и записи `a` и `b`.

## Decisions

1. Передавать `ambiguity_score_floor` из `config.toml` в `DictionaryAutoSwitch`. Для конфигов без параметра использовать `-18` и указать то же значение в `installer/config.example.toml`. Проверять порог по двум словарным скорам на первом пробеле. Скор включает существующую оценку начальной пунктуации. Для проверки нижней границы брать его до подстановки `LEARNED_BASE_SCORE`. Для проверки диапазона `[-порог текущей, порог альтернативной]` использовать дельта-скор с поправкой `learned`. Сравнение по обеим границам включительное, поскольку обычный свич требует строго превысить порог.
2. В `Input` выставлять пометку в той же ветке первого пробела, где выбирается обычный автосвич. Учитывать приоритет паттернов, блокировку по `punctuation`, обратную проверку `switch_rules`, запрет повторной коррекции и защиту от dead key. Неоднозначность означает отсутствие запроса на свич этого слова, поэтому она хранится вместе со словом в `History`. Текущее решение по автосвичу вычисляется при вводе символов и первом пробеле, а состав коррекции определяется по актуальной истории, когда `Interceptor` принимает запрос.
3. Провести через `SwitchRequest` и `Switcher` явный диапазон последних слов. Начать с локального рефакторинга однословной коррекции. Для словарного запроса расширять диапазон от текущего слова назад по истории до первого слова без пометки, с другой исходной раскладкой или с dead key в исходной либо целевой последовательности. Количество включённых слов определяется этой цепочкой.
4. Суммировать длину стирания по всему диапазону и воспроизводить слова по порядку со всеми сохранёнными пробелами под одним захватом клавиатуры. Использовать тот же диапазон для обновления раскладки в истории и снятия пометок. Защита от повторной коррекции должна действовать для каждого исправленного слова, если Backspace снова делает его текущим.
5. Сохранить одну запись `switches` на смену раскладки. Передать диапазон в фоновый поток статистики. В `a` записать исходный текст диапазона, а в `b` — тот же диапазон в целевой раскладке. Сохранить пробелы между словами. Поле `prev` по-прежнему содержит исходное слово перед словом, запустившим свич. `typing_words` получает окончательный текст каждого слова из обновлённой истории.

## Risks / Trade-offs

- При намеренном смешении раскладок следующее слово может дать ложный сигнал о предыдущих. `ambiguity_score_floor` позволяет настроить чувствительность. Слово с уверенной оценкой прерывает цепочку.
- Примеры `d` ↔ `в` и `а из коробки` зависят от словарей. Если один из вариантов отсутствует как целое слово или существующий свич уже срабатывает на префиксе неоднозначного слова, подбор `ambiguity_score_floor` сам по себе этого не исправит.
