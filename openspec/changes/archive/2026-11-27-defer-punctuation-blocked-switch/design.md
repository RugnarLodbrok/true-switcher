# Отложенная коррекция токенов, защищённых `punctuation`

## Context

`DictionaryAutoSwitch::decision` возвращает `Keep`, когда `punctuation` блокирует словарный запрос. `AutoSwitch::decision` проверяет regex текущей раскладки после словарного решения. `Input` хранит в `Word::ambiguous_delta_score` одновременно признак участия слова в `ambiguous word chain` и его вклад в скор.

## Goals / Non-Goals

Сохранить причину блокировки до выбора действия и представить участие в `ambiguous word chain` одним типом. Использовать действующие правила словарного скоринга, приоритета `switch_rules` и пригодности диапазона к перепечатыванию.

## Decisions

- Выделить в словарном решении случай, когда на первой границе слова `dscore` > `threshold`, а полное совпадение с `punctuation` блокирует запрос (срабатывает `punctuation protection`). Использовать `dscore` с применимым вкладом цепочки и `threshold` целевой раскладки, как при обычном словарном свиче. Учитывать пригодность токена для коррекции в обеих раскладках, включая dead keys.
- В `AutoSwitch::decision` сохранить приоритет паттерн-свича и проверять regex текущей раскладки для заблокированного кандидата. `Input` записывает отложенную пометку только вне паузы после движения мыши. Остальные условия оценки по-прежнему применяются в `Input`. Отложенная пометка не создаёт `PendingSwitch`.
- Заменить `Word::ambiguous_delta_score` на `Option<ChainMember>`. `ChainMember::Ambiguous { delta_score }` хранит собственный `dscore` для `ambiguous word`, а `ChainMember::DeferredByPunctuation` не содержит числового значения. Для обоих вариантов сохранить действующие правила очистки в `History`. При обработке дополнительного разделителя в `Input` также снимать пометку, если regex текущей раскладки блокировал бы словарный свич, даже при отсутствии `PendingSwitch`.
- Использовать один обход `ambiguous word chain` для словарного скоринга и выбора диапазона. Сначала определять непрерывность по наличию `ChainMember` и существующим ограничениям на границу, раскладку и dead keys. Затем для расчёта суммы брать скоры из `Ambiguous`, а для диапазона считать все элементы.

## Risks / Trade-offs

- При фильтрации по наличию скора до определения непрерывной цепочки можно потерять вклад неоднозначного слова перед отложенным токеном. Тест с `threshold = 5` и вкладом предыдущего слова `+2` различает этот случай и ошибочное участие бесконечного скора.
- Если обработать пометку сразу после `punctuation`, можно пропустить запрет `switch_rules` для текущей раскладки. Сценарий с совпадающим regex проверяет итоговый диапазон коррекции.
- Снятие пометки разрывает цепочку. Более ранние слова могут остаться в исходной раскладке. Это сохраняет один непрерывный диапазон перепечатывания в целевой раскладке.
