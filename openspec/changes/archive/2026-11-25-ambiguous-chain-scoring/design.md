# Design

## Context

`DictionaryComparison` уже рассчитывает дельта-скор слова с поправкой `learned`. Сейчас решение `Ambiguous` не передаёт этот скор, а `Word` хранит только `is_ambiguous`. При формировании словарного запроса `Input` проверяет, в какой раскладке набраны предыдущие неоднозначные слова и можно ли их безопасно перепечатать.

`LearnedRules` хранит исходные ключи для записи в TOML. При добавлении в trie и поиске регистр символов уже нормализуется через `char::to_lowercase`.

## Goals / Non-Goals

Хранить собственный дельта-скор слова на первом пробеле вместе с пометкой о неоднозначности, чтобы у них был один жизненный цикл.

## Decisions

- Проверять весь диапазон неоднозначности на первом пробеле по собственному дельта-скору текущего слова с поправкой `learned`. Передавать этот скор из решения `Ambiguous` в `Input` и хранить его в `Word` как `Option<f64>` вместо отдельного флага. Удаление последнего разделяющего пробела, коррекция и сброс истории отзывают сохранённую оценку вместе с пометкой.
- Использовать один и тот же пригодный непрерывный диапазон предыдущих неоднозначных слов для суммирования их знаковых дельта-скоров и для словарной коррекции. Сначала сложить сохранённые скоры, затем один раз умножить сумму на `AMBIGUOUS_WORD_DSCORE_MULTIPLIER = 1.0` и прибавить её к собственному скору текущего слова. Например, с порогом для третьего слова сравнивается `dscore3 + AMBIGUOUS_WORD_DSCORE_MULTIPLIER * (dscore1 + dscore2)`. Для слова без базовых скоров в обеих раскладках сохраняется действующий результат без словарного запроса и пометки.
- В `LearnedRules::increment` привести ключ обученного слова к нижнему регистру тем же посимвольным преобразованием, которое использует trie. Увеличить счётчик по этому ключу в целевой раскладке. Публиковать изменения счётчиков и trie после успешной атомарной записи.

## Risks / Trade-offs

- Расхождение условий пригодности могло бы повлиять на порог за счёт слова, которое свич оставит в исходной раскладке. Обе операции используют одно правило пригодности.
