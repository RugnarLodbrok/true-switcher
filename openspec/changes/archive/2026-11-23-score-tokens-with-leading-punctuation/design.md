# Словарная оценка токенов с начальной пунктуацией

## Context

`DictionaryAutoSwitch` хранит путь полного токена в словарном `trie` для каждой раскладки. Backspace удаляет последний элемент пути, а на первом пробеле `layout_score` временно добавляет к ключу `WORD_END` (один пробел). `LearnedRules` отдельно вычисляет счётчик по нажатиям исходного токена.

## Goals / Non-Goals

Сохранить текущую обработку Backspace, приоритет `switch_rules` и перепечатывание по полному списку нажатий. Дополнительный вариант ключа нужен только для чтения основного словаря.

## Decisions

- Компилировать `punctuation` при загрузке словарных настроек в двух формах. Для начала токена добавить `\A(?:…)`, для полного совпадения — `\A(?:…)\z`. Группировка применяет якоря ко всем веткам с `|`. Полное совпадение блокирует словарную цель только в текущей раскладке. Пустая настройка отключает обе проверки.
- Сохранить существующий кэш пути полного токена. Для второго словарного поиска отрезать начальную пунктуацию по `punctuation` от текста токена в оцениваемой раскладке. Искать остаток от корня `trie`, если он непустой. Если пунктуация занимает весь токен, оценить только полный токен.
- На первом завершающем пробеле добавить к каждому применимому словарному ключу `WORD_END` (один пробел), чтобы искать точные слова. Взять больший скор после словарного поиска. Получить счётчик `LearnedRules` по полному токену. Использовать `−18`, если ни один словарный ключ не дал положительной частоты, а счётчик положителен.

## Risks / Trade-offs

Префикс после пунктуации может пересечь порог раньше. Например, для `.git` переход возможен уже на `.g`. На первом пробеле ожидающий запрос пересчитывается по точным частотам, если коррекция ещё не началась.
