# Design

## Context

Сейчас `Word` хранит стек позиций `trie1` для каждой раскладки. `LearnedRules` при каждом запросе заново переводит поисковые `Stroke` в текст и обходит `trie2` от корня. `DictionaryAutoSwitch::layout_score` дополнительно обрезает начальную пунктуацию и ищет остаток в `trie1`.

## Goals / Non-Goals

- Общий API отвечает за поиск одного готового ключа в двух trie одной раскладки.
- Область изменения пунктуации ограничена действующей обрезкой начального совпадения при поиске. Конечная пунктуация и разбиение токена обсуждаются отдельно в `score-tokens-with-trailing-punctuation`.

## Decisions

- `score(key)` принимает одну строку и возвращает словарный скор и счётчик сохранённых примеров. Раскладка определяется при выборе пары индексов до вызова. Оба trie начинают обход от корня. `−∞` и `0` обозначают отсутствие совпадения в `trie1` и `trie2` соответственно.
- Вызывающий код переводит `Word::search_strokes()` в текст один раз на раскладку. Он применяет действующее правило начальной обрезки и вызывает `score` отдельно для исходного ключа и непустого остатка. На первой границе слова вызывающий код добавляет к каждому ключу один `WORD_END` (`" "`). Для `score` пробел является обычной частью переданного ключа.
- Вызывающий код берёт максимумы словарного скора и счётчика независимо. `comparison` применяет действующий базовый скор для совпадений только в `trie2` и рассчитывает дельта-скор из выбранных значений.
- `Word` хранит историю ввода без стека позиций trie. Backspace обновляет историю. При следующем запросе скоринга оба trie обходятся от корня по ключу, построенному из обновлённого слова.
- `LearnedRules` обслуживает запись через `teach` и действующую нормализацию при индексации. Общий API читает счётчик по готовому ключу.

## Risks / Trade-offs

При скоринге каждого символа `trie1` будет заново проходить полный ключ. Один перевод поисковых `Stroke` в текст на раскладку позволяет использовать его для обоих trie и для обрезки. Дополнительных вызовов скоринга на Backspace этот дизайн не вводит.
