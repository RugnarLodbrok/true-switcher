# Защита гомогенной пунктуации от словарного автосвича

## Context

`Input::update_auto_switch` сначала ищет цель по regex, затем вызывает `DictionaryAutoSwitch::target`. Оба этапа набора, текстовое нажатие и первый пробел, используют тот же метод выбора словарной цели.

## Goals / Non-Goals

Применить защиту при выборе словарной цели. Гомогенность токена определяется физической клавишей и состоянием Shift в каждом нажатии.

## Decisions

1. Проверять токен в `DictionaryAutoSwitch::target`, когда score проходит порог. Возвращать отсутствие словарной цели для защищённого токена. Так проверка выполняется только для кандидатов на коррекцию, а trace продолжает показывать исходный словарный score.
2. Взять первое нажатие из `Word::strokes` и сравнить с ним остальные через равенство `Stroke`, которое учитывает `key` и `shift`. Если все нажатия совпадают, преобразовать только первое через `xkb::stroke_text` в текущей раскладке. Результатом должен быть один символ из Unicode-класса `\p{P}` либо бэктик (U+0060). Завершающие пробелы хранятся отдельно, поэтому тот же критерий работает на первом пробеле.
3. Оставить управление ожидающим запросом в `PendingSwitch::update_auto`. Отсутствие словарной цели снимает ожидающий автосвич по существующему пути, а совпавший regex передаёт свою цель.

## Risks / Trade-offs

- Реальное слово может целиком выглядеть как повтор одного знака в ошибочной раскладке. Такой набор пользователь сможет исправить ручным свичем.
- Проверка кандидата, прошедшего порог, заканчивается при первом отличающемся нажатии. При ошибке преобразования первого нажатия действует результат обычной словарной оценки.
