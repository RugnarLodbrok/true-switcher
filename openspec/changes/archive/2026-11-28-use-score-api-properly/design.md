# Роли `score` и `score_separated`

## Context

Сейчас `score` вызывает `score_separated` при оценке каждого ключа. После выбора `layout_score` снова вызывает `score_separated`, а `comparison` складывает полученную пару для `dscore`.

## Decisions

- Использовать `score` при оценке ключей. Возвращать из `layout_score` выбранный ключ и его готовый `total`. Вычислять `dscore` из двух выбранных `total` и проверять их конечность в `decision`. При двух `−∞` использовать `dscore = 0`.
- Вызывать `score_separated` по выбранным ключам только при формировании вывода команды `score` или debug-лога. Запрет распространяется и на косвенные вызовы. `score` и `score_separated` могут использовать общую внутреннюю логику получения `base` и `learned`, включая базовый скор `−18` для ключа, найденного только в `trie2`.
- `split-score-penalty` сможет включить штраф в `total` разбиения при его оценке. Отображение штрафа описано в том change.
