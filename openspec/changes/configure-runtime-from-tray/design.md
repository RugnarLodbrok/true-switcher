# Настройки через трей

## Контекст

`config` загружает `Configuration` при запуске. `AutoSwitchRules` использует стартовые флаги при подготовке regex и словарей. `Switcher` читает флаги звука при создании коррекции, а `Sound` сейчас не запускает worker, если оба звука выключены. Меню трея передаёт команды жизненного цикла через очередь событий ввода. Требования к поведению описаны в [delta spec](specs/session-lifecycle/spec.md).

## Цели и границы

Применять переключатели через действующие компоненты обработки ввода и сохранять TOML с комментариями. Динамическое редактирование списка словарей, regex и клавиши переключения остаётся за пределами change.

## Решения

### Применение в работающем процессе

- Инициализировать четыре runtime-флага из `Configuration`. Передавать действия трея через очередь событий и менять флаги в потоке обработки ввода. Меню публикует применённые значения через свойства переключателей D-Bus. Для записи брать согласованный snapshot всех четырёх флагов.
- Хранить подготовленные regex и словари независимо от начальных флагов. При выборе автоматической коррекции проверять флаг соответствующего способа, сохраняя текущий приоритет regex над словарями. При выключении отменять ожидающую автоматическую коррекцию этого способа, если она ещё не началась. Хранить словарные префиксы и при выключенном автосвитче, чтобы после включения можно было учесть уже набранную часть слова.
- Выбирать флаг звука при создании коррекции по существующему `SwitchMode`. Запускать worker `Sound` при первом запросе на воспроизведение, чтобы звук можно было включить после запуска с обоими выключенными флагами.

### Ограничение на включение автосвитча

При открытии меню обновлять доступность пункта по текущему числу раскладок KDE. Перед переходом из выключенного состояния во включённое проверить число раскладок повторно, чтобы обработать изменения между открытием меню и кликом. При включённом автосвитче пункт остаётся доступен для выключения. Изменение списка раскладок само по себе флаг не меняет. Проверка конфигурации при старте и `Reload` сохраняется.

### Сохранение TOML

- При успешной загрузке удерживать исходный TOML как `toml_edit::DocumentMut` рядом с типизированной `Configuration`. Типизированные значения нужны для работы приложения, а редактируемый документ сохраняет комментарии, форматирование и неизвестные поля.
- По команде «Записать в конфиг» взять копию загруженного документа, заменить четыре булевых значения с сохранением оформления и комментариев на той же строке, добавить отсутствующие ключи и записать документ целиком. Содержимое файла на диске при этом не читается.
- Выполнять запись вне пути обработки клавиатурных событий. Сериализовать команды записи, чтобы более ранний snapshot не мог перезаписать более поздний. Записывать через временный файл в том же каталоге и заменять `config.toml` после успешной записи. Ошибки записи отправлять в лог без уведомлений в UI.

## Компромиссы

- Подготовленные правила и словари остаются в памяти, пока их переключатели выключены. Это позволяет применять изменения без повторного чтения файлов.
- Сохранённый документ может не пройти проверку при следующем `Reload`, если изменилось окружение. Сохранение идёт без валидации, а `Reload` использует существующий режим ошибки.
