# Design

## Context

`InputEventExt::instant()` уже переводит timestamp события клавиатуры в `Instant`. `PendingSwitch::Auto` хранит ожидающий запрос, который последующее событие может заменить. В `Switcher` смена раскладки выполняется до запуска worker, отправляющего синтетический ввод.

## Goals

Привязать замер к выполненному запросу и использовать общие точки замера для обоих автоматических режимов и обоих путей перехвата ввода.

## Decisions

- Сохранять `Instant` вызвавшего свич события вместе с целью и режимом в `PendingSwitch::Auto`. При замене запроса заменять и timestamp, при принятии переносить его через `SwitchRequest` в `Correction`. Так даже при обработке нескольких событий подряд замер начинается с клавиши, сформировавшей выполненный запрос.
- Взять `Instant::now()` непосредственно перед вызовом переключения раскладки. `Input::begin_correction` вызывается позже, уже после смены раскладки.
- Зафиксировать конечный `Instant` в worker сразу после возврата из `correct_words`, перед уведомлением о завершении. Использовать эту отметку для расчёта после подтверждения успешного исхода коррекции. Так ожидание обработки уведомления и освобождение перехвата не увеличат `correction_ms`.

## Risks / Trade-offs

Синтетический ввод может завершиться частично при отмене. Печатать строку только для `CorrectionOutcome::Completed` после успешного завершения перехвата, чтобы такие попытки не попадали в замеры.
