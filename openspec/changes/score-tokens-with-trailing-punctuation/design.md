# Словарная оценка токенов с конечной пунктуацией

## Context

`History` закрывает слово на первом пробеле или завершающем `strong pnt`. Оба trie ищут по `Word::search_strokes()` без краевых `strong pnt` и используют `WORD_END` (один пробел) для перехода к точному ключу. `DictionaryAutoSwitch` дополнительно оценивает остаток после начального совпадения `punctuation`. В `LearnedRules` этого дополнительного поиска пока нет. `trie1` строится по словарным частотам, `trie2` — по счётчикам сохранённых примеров.

## Goals / Non-Goals

Формировать для `trie1` и `trie2` один набор поисковых ключей с одинаковыми режимами префиксного и точного поиска. Для `teach` использовать действующий диапазон `Word::search_strokes()`, а при построении `trie2` применять действующую нормализацию краевых `strong pnt`. Проверять `punctuation protection` по полному токену текущей раскладки. При коррекции перепечатывать весь диапазон, выбранный по действующим правилам.

## Decisions

- Проверять AST `punctuation` при загрузке конфига через `regex-syntax`. Разрешать одиночный Unicode-литерал, Unicode-класс, их группировку и альтернативы. Допускать пустую строку для отключения. Квантификаторы, последовательности символов и позиции вроде `^` отклонять с ошибкой конфигурации.
- Компилировать полный шаблон одиночного символа для классификации `Stroke`. Для `punctuation protection` и краевой обрезки компилировать шаблоны серии `(?:pattern)+` с нужными якорями `\A` и `\z`. Начальный и конечный шаблоны применять к тексту `Word::search_strokes()` в оцениваемой раскладке, затем брать общий остаток между совпадениями. При пустом остатке, в том числе при пересечении совпадений, оценивать исходный ключ.
- Вычислять вариант с обрезкой один раз на раскладку и использовать его в обоих trie. Пока слово открыто, исходный ключ остаётся префиксным, а остаток становится точным при удалении конечного знака в этой раскладке. На первой фактической границе слова оба ключа становятся точными. К каждому точному ключу добавляется один `WORD_END`.
- Выбирать максимумы независимо. Словарный скор может прийти из полного ключа, а счётчик сохранённых примеров — из обрезанного. Подставлять выбранный счётчик в существующий расчёт базового скора и дельта-скора.
- Определять внутренние разделители по отдельным `Stroke` той же проверкой одиночного символа, что и для `strong pnt`. Если одно нажатие даёт пунктуацию во всех активных раскладках, `History` уже создал на нём границу слова. <codex: вот это херня и мы должны будем обсудить это отдельно>
- В каждой раскладке один раз вычислять разбиение по её внутренним разделителям и использовать его в обоих trie. Пропустить пустые части. Если остаётся две или более частей, искать все части до последней по точному ключу с `WORD_END`. Последнюю искать по точному ключу при обрезке конечной пунктуации или на первой фактической границе слова, иначе по префиксу. В `trie1` скор разбитого варианта равен минимуму скоров частей, включая `−∞` для отсутствующего ключа.
- В каждой раскладке выбрать максимум применимых словарных скоров. Для дельта-скора вычесть выбранный скор текущей раскладки из выбранного скора альтернативной, затем учесть существующую поправку `trie2`.

## Risks / Trade-offs

Конечная `weak pnt` может запустить словарный автосвич, пока слово открыто. При следующем скоринге край определяется заново. Например, после допечатывания `git;hub` точка с запятой становится внутренней. Пометки `ambiguous word` и отложенной коррекции по-прежнему создаются по действующим правилам на первой фактической границе слова.
