# Словарная оценка токенов с конечной пунктуацией

## Why

Первый `strong pnt` уже закрывает слово и запускает точный поиск без этого знака. `Weak pnt` остаётся в слове. Например, в паре US/RU нажатие `;` в US даёт `ж` в RU, поэтому после ввода `git;` словарь US ищет `git;` и может потерять совпадение с `git`.

## What Changes

- **BREAKING** — `punctuation` задаёт набор одиночных Unicode-символов. Значение по умолчанию — `` '[`~<>\p{P}]' ``. Для поиска серии знаков True Switcher сам добавляет `+` к группе. Сохранённые шаблоны с квантификаторами нужно заменить вручную.
- В каждой раскладке использовать одинаковые поисковые ключи для `trie1` и `trie2`: исходный текст `Word::search_strokes()`, остаток после краевой обрезки и части после разбиения.
- При обрезке конечной пунктуации использовать точный ключ для остатка даже у открытого слова.
- Выбирать максимальный словарный скор в `trie1` и максимальный счётчик сохранённых примеров в `trie2` отдельно.
- В каждой раскладке, где внутренняя пунктуация делит токен на части, считать минимум скоров её частей третьим вариантом словарного скора.

## Capabilities

### Modified Capabilities

- `auto-switch` — учёт краевой и внутренней пунктуации при словарной оценке и поиске сохранённых примеров.

## Impact

Изменение касается поиска в `DictionaryAutoSwitch` и `LearnedRules`, применения параметра `punctuation` и тестов дельта-скора.
