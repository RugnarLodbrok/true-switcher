# Design

## Context

`is_text_key` определяет, какие нажатия сохраняет `History` и принимает `replay_strokes`. `KeyboardOutput::new` отдельно регистрирует keycode виртуальной клавиатуры, а `is_repair_key` определяет, какие скрытые нажатия восстанавливает `Interceptor` при откате входа в захват.

## Goals / Non-Goals

**Goals**

- Использовать один список текстовых клавиш нумпада во всех трёх местах.

**Non-Goals**

- Отслеживание Num Lock для цифр и клавиши `Decimal/Delete`, изменение последовательности захвата и правил словарной оценки.

## Decisions

- Задать список в `src/history.rs` рядом с `is_text_key`. Физический keycode определяет принадлежность к списку, а действующая карта XKB определяет символ и учитывает Shift.
- Зарегистрировать список в `KeyboardOutput::new` отдельным коротким циклом. Часть keycode лежит выше `KEY_102ND`, поэтому текущий диапазон регистрации их пропускает.
- Добавить тот же список в `is_repair_key`. Откат использует исходное устройство и существующий порядок синтетических событий.

## Risks / Trade-offs

- Набор символов зависит от карты XKB. Например, `KEY_KPJPCOMMA` имеет текстовое назначение на японских клавиатурах Apple с соответствующей картой. Для раскладок без назначения сохраняется действующая обработка ошибок преобразования.
