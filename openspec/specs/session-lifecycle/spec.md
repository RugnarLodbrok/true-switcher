# Сеанс и настройки

## Purpose

Запуск, обработка ошибок конфигурации и завершение службы.

## Requirements

### Requirement: Настройки пользователя

True Switcher SHALL читать ~/.config/true-switcher/config.toml при запуске и проверять switch_key как имя клавиши Linux input.

#### Scenario: Настройки пользователя

- **WHEN** конфигурация отсутствует или содержит некорректную клавишу
- **THEN** трей показывает состояние ошибки с подробностями и позволяет запросить Reload после исправления

### Requirement: Управление через трей

True Switcher SHALL предоставлять Reload и Quit через меню в обычном режиме и при ошибке конфигурации.

#### Scenario: Управление через трей

- **WHEN** пользователь выбирает Quit
- **THEN** служба завершает работу без запроса перезапуска

### Requirement: Изменения устройств

True Switcher SHALL откладывать перезапуск при изменении отслеживаемых клавиатур до 10 секунд после последнего изменения.

#### Scenario: Изменения устройств

- **WHEN** во время ожидания поступил запрос остановки
- **THEN** остановка имеет приоритет над перезапуском с кодом 75

### Requirement: События указателя

True Switcher SHALL обрабатывать клики и потерю событий указателя независимо от перезапуска клавиатур.

#### Scenario: События указателя

- **WHEN** при запуске или Reload мышь лишь перемещается
- **THEN** программа продолжает запуск, движение само по себе не сбрасывает историю

### Requirement: Настройки через трей

True Switcher SHALL показывать в меню трея четыре независимых переключателя с их текущими значениями: автосвитч (`auto_switch`), паттерн-свитч (`pattern_switch`), звук ручного переключения (`manual_switch_sound`) и звук автопереключения (`auto_switch_sound`). Приложение SHALL применять изменения сразу в памяти.

#### Scenario: Изменение настройки

- **WHEN** пользователь меняет доступный переключатель в меню трея
- **THEN** новое значение сразу вступает в силу без перезапуска, а меню отображает новое состояние
- **AND** содержимое `config.toml` остаётся прежним

#### Scenario: Включение автосвитча при трёх и более раскладках

- **WHEN** автосвитч выключен, словари загружены и в KDE настроено более двух раскладок
- **THEN** включение автосвитча в трее недоступно, а подпись пункта указывает причину в скобках

#### Scenario: Выключение автосвитча при трёх и более раскладках

- **WHEN** автосвитч включён и в KDE настроено более двух раскладок
- **THEN** пользователь может выключить автосвитч через трей

#### Scenario: Добавление раскладки при включённом автосвитче

- **WHEN** пользователь добавляет третью раскладку KDE при включённом автосвитче
- **THEN** автосвитч остаётся включённым

#### Scenario: Reload после изменения в памяти

- **WHEN** пользователь выбирает `Reload`, имея несохранённые изменения настроек из трея
- **THEN** при перезапуске True Switcher загружает настройки из `config.toml`, а несохранённые значения теряются

### Requirement: Выбор уровня логирования через трей

В обычном режиме True Switcher SHALL показывать в трее подменю `Log level` с вариантами `off`, `error`, `warn`, `info`, `debug` и `trace`. Приложение SHALL отмечать только действующий уровень.

#### Scenario: Открытие подменю после запуска

- **WHEN** пользователь открывает `Log level` после запуска
- **THEN** меню отмечает уровень из `config.toml` или `info`, если `log_level` отсутствует

#### Scenario: Смена уровня логирования

- **WHEN** пользователь выбирает уровень в подменю `Log level`
- **THEN** приложение сразу фильтрует новые сообщения по выбранному уровню и отмечает его в подменю
- **AND** запись в `config.toml` выполняется только по команде `Save to config`

#### Scenario: Reload после смены уровня

- **WHEN** пользователь выбирает `Reload` после смены уровня
- **THEN** приложение применяет уровень из `config.toml` или `info`, если `log_level` отсутствует

### Requirement: Сохранение настроек из трея

True Switcher SHALL предоставлять отдельный пункт «Записать в конфиг». При его выборе приложение SHALL целиком записывать `config.toml` из документа, загруженного при запуске или последнем `Reload`, подставляя текущие значения всех четырёх переключателей и `log_level`. Приложение SHALL записывать `log_level` строкой в нижнем регистре. Сохранение SHALL выполняться без валидации и без уведомлений.

#### Scenario: Полная перезапись конфигурации

- **WHEN** пользователь выбирает «Записать в конфиг» и `config.toml` существует
- **THEN** приложение целиком заменяет файл, в том числе ручные правки, сделанные на диске после загрузки документа
- **AND** в записанном документе сохраняются комментарии, включая комментарии на строках изменённых полей, форматирование существующего текста и все остальные поля загруженного документа

#### Scenario: Создание отсутствующего файла конфигурации

- **WHEN** пользователь выбирает «Записать в конфиг», а файл `config.toml`, загруженный при запуске или `Reload`, был удалён
- **THEN** приложение создаёт файл из загруженного документа с текущими значениями четырёх переключателей и `log_level`

#### Scenario: Добавление отсутствующих полей

- **WHEN** пользователь выбирает «Записать в конфиг», а в загруженном документе отсутствует `log_level` или одно из полей переключателей
- **THEN** приложение добавляет отсутствующие поля с их текущими значениями

#### Scenario: Ошибка записи

- **WHEN** при сохранении возникает ошибка записи файла
- **THEN** приложение сохраняет текущие настройки в памяти и не показывает уведомление

### Requirement: Доступность словарного автосвича без словарей

Если True Switcher запущен без словарей, он SHALL показывать пункт `Auto-switch` выключенным и недоступным с пояснением о необходимости двух словарей. При `Reload` приложение SHALL определять доступность пункта по заново загруженной конфигурации и ограничениям KDE.

#### Scenario: Попытка включения без словарей

- **WHEN** пользователь пытается включить словарный автосвич через трей после запуска без словарей
- **THEN** `auto_switch` остаётся выключенным, а подпись пункта сообщает о необходимости двух словарей

#### Scenario: Подключение словарей через Reload

- **WHEN** пользователь добавляет два корректных словаря, оставляет `auto_switch = false` и выбирает `Reload` в поддерживаемой конфигурации KDE
- **THEN** `Auto-switch` становится доступным и включается через трей сразу, без повторного перезапуска
