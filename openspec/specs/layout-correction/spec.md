# Переключение раскладки

## Purpose

Переключение раскладки KDE Plasma и воспроизведение последнего слова при ручном и автоматическом исправлении.

## Requirements

### Requirement: Ручная коррекция

True Switcher SHALL использовать следующую раскладку KDE по ручному запросу.

#### Scenario: Ручная коррекция

- **WHEN** пользователь отдельно нажимает настроенную клавишу исправления
- **THEN** раскладка переключается даже при пустой истории, а при наличии подходящего слова оно удаляется и вводится заново

#### Scenario: Ручная коррекция слова с конечной пунктуацией

- **WHEN** пользователь набирает `home///////`, где каждый `/` получен через `strong pnt`, и запрашивает ручной свич
- **THEN** коррекция охватывает `home` и все семь знаков

### Requirement: Синтетический ввод

True Switcher SHALL воспроизводить физические клавиши через виртуальную клавиатуру после успешной смены раскладки.

#### Scenario: Синтетический ввод

- **WHEN** на этапе удаления произошла ошибка или поступила отмена
- **THEN** программа не начинает повторный ввод слова

### Requirement: Выбор режима захвата при свиче

True Switcher SHALL применять режим, заданный `IS_CAPTURE_ENABLED`, ко всем ручным, паттерным и словарным свичам при любом количестве исправляемых слов.

#### Scenario: Многословный свич с выключенным захватом

- **WHEN** при `IS_CAPTURE_ENABLED = false` нажатие пробела запускает словарную коррекцию нескольких слов
- **THEN** True Switcher синтетически отпускает удерживаемые клавиши через исходные устройства и начинает свич до физического отпускания пробела
- **AND** весь выбранный диапазон исправляется без `grab`

#### Scenario: Свич с включённым захватом

- **WHEN** при `IS_CAPTURE_ENABLED = true` поступает запрос на свич с любым количеством исправляемых слов
- **THEN** True Switcher применяет протокол захвата клавиатуры

### Requirement: Физический ввод без захвата

True Switcher SHALL при `IS_CAPTURE_ENABLED = false` отпускать удерживаемые клавиши через исходные устройства и продолжать обработку ввода во время коррекции.

#### Scenario: Физический ввод без захвата

- **WHEN** во время коррекции пользователь вводит текст и снова запрашивает свич
- **THEN** новый текст учитывается в текущей раскладке, повторный запрос игнорируется

### Requirement: Защита при dead key

True Switcher SHALL пропускать коррекцию слова с обнаруженной dead key в исходной или целевой последовательности.

#### Scenario: Защита при dead key

- **WHEN** для воспроизведения понадобилась бы dead key в целевой раскладке
- **THEN** коррекция отменяется до смены раскладки и удаления текста

### Requirement: Поиск qdbus

True Switcher SHALL искать исполняемую команду в порядке qdbus-qt6, qdbus6, qdbus.

#### Scenario: Поиск qdbus

- **WHEN** в разных каталогах PATH доступны qdbus и qdbus6
- **THEN** выбирается qdbus6

### Requirement: Звук переключения

True Switcher SHALL учитывать manual_switch_sound и auto_switch_sound независимо после успешной смены раскладки.

#### Scenario: Звук переключения

- **WHEN** обе настройки опущены
- **THEN** ручной свич бесшумен, автоматический сопровождается коротким сигналом

### Requirement: Запоминание ручной коррекции с Shift

При нажатии `Shift + switch_key` True Switcher SHALL выполнить ручную коррекцию и после успешного перепечатывания слова увеличить на единицу счётчик исправленного текста в получившейся раскладке в `learned-rules.toml`. Ключ для увеличения счётчика SHALL вычисляться из исправленного текста в нижнем регистре после удаления краевых `strong pnt` по фактическим нажатиям. Для отмены автосвича и исправления собственного ввода действует один механизм.

#### Scenario: Коррекция до конца слова

- **WHEN** пользователь нажимает `Shift + switch_key`, исправляет набранную часть слова и затем дописывает его
- **THEN** сохраняется только исправленная часть без завершающих пробелов

#### Scenario: Повторное сохранение

- **WHEN** пользователь дважды успешно исправляет один и тот же текст в одну и ту же раскладку через `Shift + switch_key`
- **THEN** счётчик этой пары текста и раскладки увеличивается на два

#### Scenario: Коррекция в разном регистре

- **WHEN** пользователь сохраняет `Hello` и `HELLO` в US через `Shift + switch_key`
- **THEN** обе коррекции увеличивают счётчик одного ключа `hello` в US

#### Scenario: Словарный автосвич выключен

- **WHEN** коррекция через `Shift + switch_key` успешно перепечатывает слово при выключенном `auto_switch`
- **THEN** счётчик сохраняется и доступен при последующем включении `auto_switch` без перезапуска

#### Scenario: Коррекция без сохранённого примера

- **WHEN** ручная коррекция запрошена без Shift либо `Shift + switch_key` не привёл к успешному перепечатыванию слова
- **THEN** счётчики сохраняют прежние значения

#### Scenario: Обучение с краевой strong punctuation

- **WHEN** `teach` успешно перепечатывает слово с начальной или конечной `strong pnt`
- **THEN** коррекция охватывает все нажатия слова, а сохранённый ключ содержит только текст без краевых `strong pnt`

#### Scenario: Semi-strong punctuation набрана обычным нажатием

- **WHEN** в исправленном слове есть символ, который можно набрать как `strong pnt`, но фактическое нажатие им не является
- **THEN** этот символ остаётся в ключе `teach`

### Requirement: Время автоматической коррекции

True Switcher SHALL после каждой успешной коррекции по словарю или паттерну передавать в лог одно сообщение уровня `INFO` в формате `correction timing: decision_ms=12.3 correction_ms=23.4`. Оба интервала SHALL выражаться в миллисекундах с одной цифрой после десятичной точки. `decision_ms` SHALL измерять время от нажатия клавиши, вызвавшей свич, до начала переключения раскладки, а `correction_ms` SHALL измерять время от начала переключения до завершения отправки синтетического ввода.

#### Scenario: Словарный автосвич на пробеле

- **WHEN** первый пробел формирует словарный запрос и коррекция успешно завершается
- **THEN** в замере `decision_ms` используется timestamp нажатия пробела, включая время ожидания перед началом переключения

#### Scenario: Паттерн-свич заменяет ожидающий запрос

- **WHEN** нажатие клавиши формирует запрос на паттерн-свич взамен ожидающего запроса и коррекция успешно завершается
- **THEN** в замере `decision_ms` используется timestamp нажатия, сформировавшего запрос на паттерн-свич

#### Scenario: Завершение отправки синтетического ввода

- **WHEN** отправка синтетического ввода для успешной автоматической коррекции завершилась
- **THEN** `correction_ms` включает время переключения раскладки, удаления и повторного ввода текста до завершения этой отправки

#### Scenario: Коррекция вне условий замера

- **WHEN** коррекция выполняется вручную либо автоматическая коррекция отменена, прервана или завершилась ошибкой
- **THEN** сообщение `correction timing` для этой коррекции отсутствует
